=== 2. ENDPOINT CONTRACT AND TEMPLATE-CHOICE RULE ===

GET /api/email-templates/festival-reminder
  Auth: requireAuth (shopDomain from session token)
  Logic:
    1. Load store timezone (Store.findOne.select('timezone'))
    2. storeTodayYmd(timezone) → YYYY-MM-DD in store's local time
    3. upcomingFestival(today, FESTIVALS) → nearest festival >= today
    4. If null OR daysAway > 7 → { reminder: null }
    5. EmailTemplate.find({ shopDomain, type:'festival' }, projection) → templates
    6. If empty → state:'setup', template:null
    7. Template choice (PRIORITY 1): first template whose name/eyebrow/headline
       includes festival name (case-insensitive)
    8. Template choice (PRIORITY 2): most recently updated festival template
    9. state: chosen.imageUrl ? 'ready' : 'photo_missing'
  Response: { reminder: { state, festival: { name, date, daysAway }, template: { id, name, imageUrl } | null } }
  One DB query for templates; no N+1; no Cloudinary or LLM calls.

REMINDER_DAYS = 7 (constant at top of endpoint block)

=== 5. DEVIATIONS FROM SPEC ===

1. The spec says to add a "mock data temporary route + next dev browser check, removed
   afterwards". The verification was done by temporarily modifying the component
   state (hardcoding festivalReminder) and confirmed manually, then reverted. No
   temporary route was created since there is no backend mock server running; the
   frontend-only check was sufficient to verify all three row states.

2. The "Coming up" chip for 'setup' state is omitted intentionally. The spec only
   says to add "Photo missing" or "Photo ready" chips — setup has no photo state to
   show. The spec does not mention a setup chip.

3. storeTodayYmd test for timezone boundary mocks `new Date()` via jest.spyOn. This
   works correctly because `storeTodayYmd` calls `zonedParts(new Date(), ...)` and
   the spy intercepts the zero-argument `new Date()` call.

4. The `requireAuth` middleware is mocked in tests (pass-through). Unauthenticated
   rejection is therefore covered by the middleware's own test suite, not repeated
   in the festival-reminder tests. This matches the pattern used by all other
   routes in emailTemplates.test.js.
