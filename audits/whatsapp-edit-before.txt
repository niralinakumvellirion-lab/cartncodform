PART 1 — WaComposer today (CustomerDetail.jsx:500–666)
===================================================================

How the selected suggestion text is shown:
  - Suggestion cards show a short preview string: s.preview(customer)
    (CustomerDetail.jsx:592–594) — italic, read-only, 1 line, ~80 chars.
  - This preview is NOT the full template text. It's a hard-coded short
    sentence in WA_SUGGESTION_TYPES. The full template text lives on the
    backend (WA_TEMPLATES, whatsapp.js:50–93).
  - There is NO editable textarea. The seller sees only a preview.
  - There is NO character counter, no name/store chip inserts, no reset.

What is sent to POST /send (customerShared.jsx:204–217):
  Body: { profileId, purpose, template? }
  - profileId: string (profile._id)
  - purpose: selected.purpose ('followup' | 'order')
  - template: selected.key (or undefined for 'say_hello' fallback)
  - No `message` field. Text is built entirely server-side.

handleSend (CustomerDetail.jsx:512–518):
  - 'say_hello' fallback → template undefined → backend uses default
    waFollowupMessage()
  - All other types → template = key (e.g. 'cart_reminder')

PART 2 — Backend message building (whatsapp.js)
===================================================================

Final text built at lines 255–261:
  1. If `tpl` (named template): tpl.build(firstName, storeName, storeLink)
  2. Else if purpose==='order': waOrderMessage(firstName, shop, storeLink)
  3. Else (default followup): waFollowupMessage(firstName, shop, storeLink)

Name/store substitution:
  - firstName: resolveFirstName(profile) (lines 155–162) — derived from
    email local-part (first segment before . _ +), capitalised.
    Falls back to 'there' when no email.
  - storeName: shop.split('.')[0]  (line 256)

Store link + ccf_job (lines 252–253):
  storeLink = `https://${shop}?ccf_src=whatsapp&ccf_job=${job._id}`
  The link is embedded INSIDE each template's build() call. It's the
  ctaUrl arg passed to build(). Currently it's woven into the middle of
  the message text (e.g. "Complete your order: <link>\n\nReply STOP").

  Important: the link is built AFTER the job is created (line 240–250),
  so the ccf_job ID is always present. The link is inside the template
  body, not appended after it.

ScheduledJob fields saved (lines 240–250):
  { shopDomain, profileId, channel:'whatsapp', status:'sent',
    sentAt, runAt, stepIndex:0, ruleId:null, purpose }
  templateKey: NOT stored on the job.
  messageText: NO field — the sent text is NOT stored anywhere.
    ScheduledJob has: `payload` (Mixed, used for push title/body/imageUrl),
    `reason` (String, human-readable why), but neither holds WA text.

wa.me URL encoding (line 262):
  `https://wa.me/${digits}?text=${encodeURIComponent(message)}`
  The full message (including storeLink) is URL-encoded in the query
  string. WhatsApp pre-fills this as the compose text for the sender.

Returns: { url, jobId, purpose } — url is the wa.me deep link.

SUMMARY OF GAPS
===================================================================
1. No server field `message` on POST /send — custom text is impossible today.
2. No editable textarea in WaComposer — seller sees only short preview.
3. Sent message text not stored on ScheduledJob — no `messageText` field.
4. Store link is embedded mid-template, not appended after; the new
   "always append" requirement needs to change how the link is added when
   `message` is present.
5. Today.jsx and Customers.jsx send with no template/message — they must
   remain on the default path and must not be broken.
