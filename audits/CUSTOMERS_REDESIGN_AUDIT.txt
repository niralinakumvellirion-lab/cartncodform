  Notes (observations only):
  * Still a Polaris <Page title="Customers"> screen (NOT the div-based redesign
    Today.jsx got). secondaryActions = one "Refresh" button -> loadData.
  * Data: two parallel apiGet calls on mount / refresh:
      GET /api/profiles/:shop/profiles?limit=50    -> profRes.profiles
      GET /api/profiles/:shop/signals?limit=200    -> sigRes.signals
    Signals are reduced into signalCountMap { profileId -> count }. sig.profileId
    may arrive scalar OR as a populated object ({_id}); both handled (37-40).
  * Master/detail in ONE component: when selectedProfileId is set, the whole
    screen is REPLACED by <ProfileScreen shop profileId onBack> (early return,
    line 56). Row onClick sets selectedProfileId. No routing — the detail view
    has no URL, so it is lost on refresh / cannot be deep-linked.
  * IndexTable: selectable=false; itemCount = profiles.length (NOT the API's
    `total`); loading passthrough; 6 columns:
      Identifier  emails[0] || phones[0] || "Anonymous <last 6 of _id>"
      Stage       Badge, tone by stage (customer=success, identified=info,
                  lapsed=warning, else default); label p.stage || 'anonymous'
      Signals     Badge tone="attention" with the count, else em-dash
      Channels    <Badge>Push</Badge> if channels.push.subscribed;
                  <Badge>Email</Badge> if channels.email.address
      LTV         rupee + orders.ltv (en-IN) when > 0, else em-dash
      Last seen   lastSeenAt -> toLocaleDateString('en-IN'), else em-dash
  * No pagination UI — fixed limit=50 profiles / limit=200 signals; the API's
    `total` and `page` params are unused by this screen.
  * error -> a critical Banner above the Card; empty -> IndexTable emptyState.

 92	/**
 93	 * GET /api/profiles/:shopDomain/profiles
 94	 * Query: limit (default 50, max 200), page (default 0)
 95	 * -> { profiles, total }  (most recently active first)
 96	 */
 97	router.get('/:shopDomain/profiles', requireAuth, requireStoreOwner, async (req, res) => {
 98	  try {
 99	    const shop = req.params.shopDomain.trim().toLowerCase();
100
101	    let limit = parseInt(req.query.limit, 10);
102	    if (!Number.isFinite(limit) || limit < 1) limit = 50;
103	    if (limit > 200) limit = 200;
104
105	    let page = parseInt(req.query.page, 10);
106	    if (!Number.isFinite(page) || page < 0) page = 0;
107
108	    const [profiles, total] = await Promise.all([
109	      Profile.find({ shopDomain: shop })
110	        .sort({ updatedAt: -1 })
111	        .skip(page * limit)
112	        .limit(limit)
113	        .select('identifiers stage orders channels lastSeenAt updatedAt'),
114	      Profile.countDocuments({ shopDomain: shop }),
115	    ]);
116
117	    return res.json({ profiles, total });
118	  } catch (err) {
119	    console.error('[profiles] GET profiles error:', err.message);
120	    return res.status(500).json({ error: 'Failed to fetch profiles' });
121	  }
122	});

  Notes (observations only):
  * requireAuth + requireStoreOwner; scoped by :shopDomain (trim + lowercase),
    never by email.
  * limit default 50, clamped 1..200. page default 0, >= 0. Offset paging via
    .skip(page * limit).
  * Sorted updatedAt desc ("most recently active first").
  * .select() projection: identifiers, stage, orders, channels, lastSeenAt,
    updatedAt (plus _id). So the client's p.orders.ltv, p.channels.push.
    subscribed, p.channels.email.address, p.identifiers.emails/phones are all
    present. messages[] and signals are NOT returned here (the Customers
    screen gets signal counts from the separate /signals call).
  * Response shape { profiles, total }. The Customers screen consumes
    `profiles` only; `total` is returned but unused client-side.
