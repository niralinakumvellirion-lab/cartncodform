Date: 2026-10-12

BUG REPORTED
------------
After commit 0ff1081 (product link preview), CustomerDetail's WhatsApp
tab (WaComposer) shows ONLY the "LINK IN MESSAGE" product chips and
the "Quiet hours respected" footer. Suggested-message cards, message
editor, link-preview card, link note, and send button are all missing.


RENDER GATE AUDIT (CustomerDetail.jsx, WaComposer function)
------------------------------------------------------------
Render gates, in JSX order (lines are post-0ff1081):

  Line 686: {suggestions.length > 0 && (...)}
    → Suggestion cards. Hidden when rankWaSuggestions() returns [].

  Line 740: {(waProfile?.recentProducts?.length > 0) && (...)}
    → Product chips ("LINK IN MESSAGE"). Confirmed rendering.

ROOT CAUSE ANALYSIS
-------------------
For the described symptom — only product chips show — BOTH of these
conditions must be false simultaneously:

  (a)  suggestions.length > 0    →  no suggestion cards
  (b)  selected !== null         →  no editor / send / link-preview

For (a) and (b) to be false with canWa = true (WaComposer is rendered):

  rankWaSuggestions() source (lines 422-438):

    function rankWaSuggestions(customer, waProfile) {
      const ranked = WA_RANK_ORDER
        .map(key => WA_SUGGESTION_TYPES.find(t => t.key === key))
        .filter(t => t && t.eligible(customer, waProfile));

      if (ranked.length === 0 && waProfile?.canFollowup) {
        return [{ key: 'say_hello', ... }];   // ← always fires when canFollowup
      }
      return ranked.slice(0, 3);
    }

  CASE A – canFollowup = true:
    Fallback `say_hello` always fires → suggestions = [say_hello],
    selected = say_hello. Suggestion cards + editor MUST render.
    *** This case cannot reproduce the bug. ***

  CASE B – canFollowup = false, canOrder = true, no eligible order
    suggestions (e.g., customer has phone but no orders and opted out
    of follow-ups):
    - ranked = [] (no cart, no orders)
    - canFollowup is false → say_hello fallback does NOT fire
    - returns []
    → suggestions.length === 0, selected = null
    → Suggestion cards HIDDEN, editor HIDDEN, send HIDDEN.
    → Only product chips (recentProducts.length > 0) render.
    *** This reproduces the symptom exactly. ***

REGRESSION LINK TO 0ff1081:
  Before 0ff1081, GET /profile did not return recentProducts.
  waProfile.recentProducts was undefined → chips conditional false →
  WaComposer rendered as an entirely blank panel for these customers.

  After 0ff1081, GET /profile now returns recentProducts. For a
  customer who browsed products but opted out of follow-ups with no
  orders, product chips now render while everything else remains empty.
  The newly visible chips make the blank state look like a regression.

  Additionally: the product selector conditional at line 740 lacks an
  Array.isArray guard; if the API ever returns recentProducts as a
  non-array truthy value (e.g., during an API error recovery path),
  .map() at line 747 would throw, breaking the entire WaComposer render.

ROOT CAUSE (file:line):
  CustomerDetail.jsx:427-438 — rankWaSuggestions() returns [] when
  canFollowup=false AND canOrder=true AND no eligible order suggestions.
  Combined with 0ff1081's recentProducts chips, this creates a panel
  that shows only product chips while all other blocks remain hidden.

  CustomerDetail.jsx:740 — missing Array.isArray guard on recentProducts
  before the .map() at line 747.
