  Before: namespace: 'cartncodform'  (requires write_metafields scope — BLOCKED)

write_metafields scope. In the Admin GraphQL API, passing namespace: '$app'
in metafieldsSet is resolved by Shopify to the app's own reserved namespace

  shop.metafields.$app.quantity_tiers

STEP 1 — Theme app block
═══════════════════════════════════════════════════════════

New files:
  extensions/cartncodform-embed/blocks/quantity-tiers.liquid
  extensions/cartncodform-embed/assets/ccf-tiers.js

Block schema:
  name: "Quantity Tiers"
  target: "section"
  templates: ["product"]
  presets: [{ name: "Quantity Tiers" }]
  settings: []

Config source (server-rendered Liquid):
  {%- assign qt_mf = shop.metafields.$app.quantity_tiers -%}
  Reads the app-reserved shop metafield written by tierSync.js.
  The parsed value is serialised as JSON into:
    <script type="application/json" id="ccf-qt-config">{{ qt_config | json }}</script>
  If metafield is blank: no config element rendered, JS falls back to
  GET /apps/cartncodform/discount-config (App Proxy, Shopify adds signature).

Design mode (Liquid):
  {% if request.design_mode %} renders a dashed-border placeholder div.
  JS also checks window.Shopify.designMode as a second guard.

ccf-tiers.js behaviour:
  - IIFE, no global leaks
  - CSS injected once, all classes prefixed .ccf-qt-*
  - On init: if designMode → placeholder; if disabled/empty → removeChild
  - Cards: <button type="button" aria-pressed>, with badge (top edge),
    "Buy N" label, "X% off" chip, per-item discounted price after variant fetch
  - Click: sets form[action*="/cart/add"] input[name="quantity"], dispatches
    input + change events; clicking active card → sets qty to 1
  - Manual qty change: updates active card (highest matching tier)
  - COD link sync: updates href on any a[href*="cod-form"] to include
    &quantity=N, enabling merchants with a static COD button to pass qty
  - Variant change: listens to variant:change and variantChange events;
    also re-fetches via /products/{handle}.js on input[name="id"] change
  - Prices: fetched from /products/{handle}.js (minor units = paise)
    formatted via Shopify.formatMoney or Intl.NumberFormat
  - Rounding: Math.round((raw + Number.EPSILON) * 100) / 100 — identical to
    backend/utils/quantityTiers.js discountedUnitPrice
  - Savings: shown as "You save ₹X" (total over selected qty) when tier active
  - Never throws on bad JSON, missing form, missing product handle

STEP 2 — COD form + order
═══════════════════════════════════════════════════════════

── How the COD form gets its quantity today ──────────────────

BEFORE Phase 4b: The cod-form route did NOT accept a quantity parameter.
The form HTML had <input type="number" name="quantity" min="1" value="1">.
The form was always pre-filled with qty=1 regardless of the PDP form qty.
The COD form URL (opened by the merchant's theme button or ccf-push.js) did
not include &quantity=N.

CHANGE (smallest): cod-form now accepts ?quantity=N from the URL query string.
  const quantityParam = Math.max(1, parseInt(req.query.quantity || '1', 10) || 1);
  BOOT.quantity = quantityParam
  <input ... value="${escapeHtml(String(quantityParam))}" ...>

Additionally, ccf-tiers.js (Step 1) updates any a[href*="cod-form"] links on
the page whenever the selected tier changes, so merchants with a static COD
button automatically get the current qty in the URL.

── quantityTiers in BOOT ─────────────────────────────────────

The cod-form route already loaded DiscountConfig (birthday config). Extended
that single DB query to also extract quantityTiers. BOOT now includes:
  quantityTiers: { enabled, tiers[{minQty, percent, badge}], heading,
                   accentColor, layout }

Client-side inline JS in cod-form updates the price display (#ccf-price-line)
on quantity change:
  - No tier: "Price: ₹999 × 3 = ₹2,997"
  - With tier: "3 × ₹849.15 = ₹2,547.45 — 15% off\nYou save ₹449.55"

── Server-side tier discount in /cod-order ───────────────────

Server recomputes the tier discount from DB (never trusts client fields):
  const { pickTier, discountedUnitPrice } = require('../utils/quantityTiers');
  const cfg = await DiscountConfig.findOne({ shopDomain: shop }).lean();
  const tier = pickTier(qt.tiers, cleanQty);
  const discUnit = discountedUnitPrice(cleanPrice, tier.percent);
  const saving = Math.round((cleanPrice - discUnit) * cleanQty * 100) / 100;
  tierDiscount = { percent: tier.percent, amount: saving };

CodOrder model: added tierDiscount: { percent: Number, amount: Number }.
Stored alongside the order. Defaults to { percent: 0, amount: 0 } when no
tier applies.

── How discounts are applied to COD orders ────────────────────

The COD order system stores orders in MongoDB (CodOrder collection). There is
NO Shopify order or draft order created. The tier discount is stored on the
CodOrder document as { percent, amount }. It represents the saving displayed
to the customer and recorded for merchant reporting. No Shopify discount
mechanism is used for COD orders.

── Birthday code vs tier discount on COD ─────────────────────

The COD form and /cod-order route do NOT accept discount codes. There is no
discount code field, no Shopify checkout, and no code-application logic.
NOTHING CHANGED for birthday vs tier on COD — they cannot conflict because
the discount-code path does not exist in the COD flow.
