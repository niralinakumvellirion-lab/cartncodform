3. fontFamily / lineHeight SET INLINE ON EVERY PREVIEW BUTTON/INPUT
====================================================================
Confirmed present on every <button> and <input> across both preview
components:
  ClassicPreview: allowBtnEl (Split/Card, shared), Banner's own Allow
    button, denyEl (Split/Card, shared) — all via fontFamily: font,
    lineHeight: 1.2. Both email inputs (Card's own, Split's
    discountFieldsEl) — fontFamily: font, lineHeight: 1.2.
  StyleCardPreview: allowBtnCommon.style (Flash Sale + Gift Reveal
    Allow, shared) — fontFamily: font, lineHeight: 1.2. denyLinkStyle()
    and pillDenyStyle (Flash Sale/Gift Reveal Deny, all variants) —
    same. Both email inputs (Flash Sale's, Gift Reveal's) — same.
  ClosePreviewButton (shared by every layout's X): fontFamily: 'inherit'
    (matches ccf-push.js's own closeBtn styles, which never set
    font-family either — the × glyph itself doesn't depend on the
    popup's chosen font, so 'inherit' here is intentionally different
    from the merchant's `font` value used elsewhere, mirroring reality).

`font` in each component is `cfg.fontFamily || 'inherit'` — when the
merchant hasn't set a custom font, this inline value literally IS the
CSS keyword 'inherit', which still correctly short-circuits BOTH the
Tailwind Preflight (`button{font-family:inherit}`) and Polaris
(`button{font-family:var(--p-font-family-sans)}`) competing rules found
in the prior audit, since an INLINE style always wins over either
stylesheet rule regardless of which one has higher source-order
priority — the button no longer needs to fall through to either
tag-selector rule to resolve its font at all.

lineHeight: 1.2 was chosen as a plain, safe default (ccf-push.js's own
Allow/Deny buttons never set an explicit line-height either — only its
close buttons do, for glyph centering, which the preview's
ClosePreviewButton already replicates via lineHeight: size + 'px').
