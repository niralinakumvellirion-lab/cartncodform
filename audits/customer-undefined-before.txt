ROOT CAUSE IDENTIFIED
============================================================

File : backend/routes/profiles.js (lines 207-216, commit 4c9bc11)
Bug  : { ...p } spread on a Mongoose 8 document only copies the document's
       OWN enumerable properties: `$__` (internal state) and `_doc` (data).
       Schema fields (_id, identifiers, channels, etc.) are defined as prototype
       getters, NOT own enumerable properties. So { ...p } gives:
         { '$__': {...}, '_doc': { _id: ObjectId, identifiers: {...}, ... } }
       and the frontend receives p._id === undefined for every profile row.
       This was introduced in commit 4c9bc11 ("WhatsApp step 1b") which added:
         return { ...p, hasWhatsappReachable };  ← was: return res.json({ profiles, total })
       Before that commit, profiles were returned directly (Mongoose docs), and
       JSON.stringify called .toJSON() on each, giving top-level _id.

Verified:
  node -e "const m=require('mongoose');const s=new m.Schema({name:String});
  const M=m.model('T',s);const d=new M({name:'x'});
  console.log(Object.keys({...d}));"
  → [ '$__', '_doc' ]   ← _id is NOT at the top level

3. WHICH SITE(S) CAN PRODUCE UNDEFINED AND WHY
============================================================

PRIMARY: Customers.jsx (both views, lines 370 and 506)
  - `p` comes from the profiles API response
  - profiles API spreads Mongoose docs: { ...p } gives { '$__', '_doc' } NOT fields at top level
  - p._id = undefined → encodeURIComponent(undefined) = "undefined" → URL = /admin/customers/undefined

SECONDARY (not a source, but amplifies the 500): events.js journey route
  - Accepts profileId = "undefined" (the string) because it's a non-empty string
  - Passes it to Profile.findOne({ _id: "undefined" }) which throws CastError → 500
  - Fix: validate with mongoose.Types.ObjectId.isValid()
