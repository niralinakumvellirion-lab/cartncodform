  export async function apiGet(path) {
    const url = `${BACKEND_URL}${path}`;
    const token = await getAuthToken();
    const headers = token ? { Authorization: `Bearer ${token}` } : {};

    let res;
    try {
      res = await fetch(url, { cache: 'no-store', headers });
    } catch (err) {
      throw new Error(describeNetworkError(err, 'GET', url));
    }

    // Retry once with a fresh token on 401 (expired token).
    if (res.status === 401 && token) {
      const freshToken = await getAuthToken(true);
      if (freshToken) {
        try {
          res = await fetch(url, {
            cache: 'no-store',
            headers: { Authorization: `Bearer ${freshToken}` },
          });
        } catch (err) {
          throw new Error(describeNetworkError(err, 'GET', url));
        }
      }
    }

    if (!res.ok) {
      const body = await res.text().catch(() => '');
      throw new Error(`GET ${path} failed (${res.status}): ${body}`);
    }
    return res.json();
  }

  export async function apiSend(path, method, body) {
    const url = `${BACKEND_URL}${path}`;
    const token = await getAuthToken();
    const headers = {
      'Content-Type': 'application/json',
      ...(token ? { Authorization: `Bearer ${token}` } : {}),
    };

    let res;
    try {
      res = await fetch(url, { method, headers, body: JSON.stringify(body) });
    } catch (err) {
      throw new Error(describeNetworkError(err, method, url));
    }

    // Retry once with a fresh token on 401 (expired token).
    if (res.status === 401 && token) {
      const freshToken = await getAuthToken(true);
      if (freshToken) {
        try {
          res = await fetch(url, {
            method,
            headers: {
              'Content-Type': 'application/json',
              Authorization: `Bearer ${freshToken}`,
            },
            body: JSON.stringify(body),
          });
        } catch (err) {
          throw new Error(describeNetworkError(err, method, url));
        }
      }
    }

    const data = await res.json().catch(() => ({}));
    if (!res.ok) {
      throw new Error(data.error || `${method} ${path} failed (${res.status})`);
    }
    return data;
  }

HOW THE TOKEN IS FETCHED — getAuthToken (lines 27-46):
  async function getAuthToken(forceRefresh = false) {
    const isStale = Date.now() - cachedTokenAt > TOKEN_TTL_MS;
    if (!forceRefresh && cachedToken && !isStale) {
      return cachedToken;
    }
    try {
      const res = await fetch('/api/token', { cache: 'no-store' });
      if (!res.ok) { cachedToken = null; return null; }
      const data = await res.json();
      cachedToken = data.token || null;
      cachedTokenAt = Date.now();
      return cachedToken;
    } catch { cachedToken = null; return null; }
  }

      if (!session?.user?.email) -> 401 { error: 'Not authenticated' }

HOW IT'S ATTACHED:
  - Both helpers call `await getAuthToken()`, then set
    `Authorization: Bearer <token>` on the fetch to BACKEND_URL.
  - apiSend also always sets `Content-Type: application/json`.
  - If getAuthToken() returns null (not signed in / mint failed),
    the request is sent WITH NO Authorization header (headers = {}
    / just Content-Type) — the backend then 401s.

CACHE MECHANISM (lines 20-25 + getAuthToken):
  - Module-level in-memory cache: `let cachedToken = null;`
    `let cachedTokenAt = 0;`
  - `const TOKEN_TTL_MS = 10 * 60 * 1000;`  (10 minutes)
  - getAuthToken() returns the cached token unless: forceRefresh
    is true, OR cachedToken is null, OR it's older than 10 min
    ("token itself expires at 15" per the comment — 5 min safety
    margin).
  - Invalidation: a 401 from the backend triggers ONE retry via

    refresh). Not persisted.

FULL LOGIC — requireAuth (lines 9-36):
  - Reads `Authorization` header; token = the part after
    'Bearer ' (or null).
  - No token -> 401 { error: 'Missing Authorization header' }.
  - secret = process.env.BACKEND_JWT_SECRET;
      if unset -> logs '[auth] BACKEND_JWT_SECRET not configured
      on backend' and 500 { error: 'Server auth misconfigured' }.
  - payload = jwt.verify(token, secret)
      -> jsonwebtoken, default algorithm handling (HS256 for a
         string secret), verifies signature + exp.
  - email = payload.email || (payload.user && payload.user.email)
      -> no email claim -> 401 { error: 'Token missing email claim' }.
  - SETS ON req:  req.userEmail = String(email).trim().toLowerCase()
  - next()
  - Any verify throw (bad sig / expired / malformed) -> logs
    '[auth] Token verification failed: <msg>' and 401
    { error: 'Invalid or expired token' }.
  -> LIBRARY: jsonwebtoken.  SECRET: process.env.BACKEND_JWT_SECRET
     (an app-internal shared secret, same value the frontend
     /api/token route signs with).  SETS: req.userEmail (lowercased).

FULL LOGIC — requireStoreOwner (lines 44-71):
  - Requires requireAuth to have run first (needs req.userEmail).
  - shopDomain = (req.params.shopDomain || '').trim().toLowerCase()
      -> empty -> 400 { error: 'shopDomain required' }.
  - LOADS: store = await Store.findOne({ shopDomain })
      -> not found -> 404 { error: 'Store not found' }.
  - CHECKS:
      * !store.ownerEmail -> warn + 403 { error: 'Store has no
        owner on record' }.
      * store.ownerEmail !== req.userEmail -> 403 { error: 'Not
        authorized for this store' }.

    downstream handlers / requirePaidPlan).
  - next()
  - Any throw -> logs '[auth] requireStoreOwner error: <msg>' and
    500 { error: 'Authorization check failed' }.
  -> The ownership model is purely EMAIL-BASED: the caller's
     verified email (from the JWT) must equal Store.ownerEmail
     (set at OAuth-callback time from the Google-login email or
     the shop's contact email).

E2) FRONTEND CHANGES to swap /api/token -> App Bridge session token
  Context: /admin runs embedded in Shopify Admin; App Bridge v4 is
  already loaded (CDN <Script> + <meta name="shopify-api-key">).
  The v4 global exposes `window.shopify` with `shopify.idToken()`
  -> Promise<string> (a fresh, ~1-minute session/ID token signed
  by Shopify). `@shopify/app-bridge-react` (installed, unused)
  also offers `useAppBridge()` but that's a React hook and
  lib/api.js is a plain module.

  Changes:
  (1) lib/api.js — replace getAuthToken()'s body:
        OLD: fetch('/api/token') -> data.token
        NEW: return await window.shopify.idToken()
             (guard: if (typeof window === 'undefined' ||
              !window.shopify?.idToken) return null;)
      Keep the same "return null on failure -> request sent
      unauthenticated -> backend 401" contract, and keep the
      one-shot 401 retry (still useful).
  (2) TOKEN CACHE — the current TTL is 10 min; a Shopify session
      token lives ~60s. Either:
        - drop TOKEN_TTL_MS to ~30-45s, OR
        - remove the module cache entirely and call
          shopify.idToken() every request (App Bridge caches/
          refreshes internally and the call is cheap/local). The
          latter is simpler and less error-prone; recommended.
  (3) /api/token route (frontend/app/api/token/route.js) becomes
      DEAD for /admin. Leave it only if the separate NextAuth
      `/dashboard` UI is still shipping; otherwise delete it
      along with its `jsonwebtoken` + `authOptions` imports.
  (4) The App Bridge script + <meta name="shopify-api-key"> are
      ALREADY in admin/page.js — no new markup. Optionally add
      `@shopify/app-bridge-react`'s <AppProvider>/<NavMenu> etc.
      later, but not required just for idToken().
  (5) NO new npm install needed (app-bridge-react already a dep;
      idToken() comes from the CDN global). `jsonwebtoken` in the
      frontend can eventually be removed.
  (6) Non-embedded contexts (opening /admin directly, or SSR):
      `window.shopify` is undefined -> getAuthToken() returns null
      -> every call 401s. That's acceptable for an embedded-only
      page, but worth an explicit "must be opened from Shopify
      Admin" empty state.

E3) BACKEND CHANGES to verify a Shopify session token (instead of
    the BACKEND_JWT_SECRET JWT)
  A Shopify session/ID token is a JWT:
    - alg HS256, signed with the app's CLIENT SECRET
      (process.env.SHOPIFY_API_SECRET — ALREADY set on the
      backend, used today for webhook/OAuth HMAC).
    - claims: iss = "https://{shop}.myshopify.com/admin",
      dest = "https://{shop}.myshopify.com",
      aud = <client_id> (process.env.SHOPIFY_API_KEY — already
      set),
      sub = Shopify user id, sid = session id,
      exp / nbf / iat (short, ~1 min).
    - IT CONTAINS NO EMAIL.

  requireAuth changes:
  (1) Verify with SHOPIFY_API_SECRET, not BACKEND_JWT_SECRET:
        jwt.verify(token, process.env.SHOPIFY_API_SECRET,
                   { algorithms: ['HS256'] })
      and additionally assert:
        - payload.aud === process.env.SHOPIFY_API_KEY
        - payload.iss and payload.dest resolve to the SAME shop
          host (strip "/admin" from iss)
        - exp/nbf within a small clock-skew allowance
      (Or use @shopify/shopify-api's
       `shopify.session.decodeSessionToken(token)` which does all
       of the above — would be a new backend dependency.)
  (2) STOP setting req.userEmail from the token (there is no
      email). Instead set, e.g.:
        req.shopDomain     = host parsed from payload.dest
                             ("cartncod-form.myshopify.com")
        req.shopifyUserId  = payload.sub
      Everything downstream that reads req.userEmail must change.
  (3) BACKEND_JWT_SECRET is no longer needed for the embedded
      flow (keep it only if /dashboard's NextAuth JWT path stays).

  requireStoreOwner changes:
  (4) The email match (store.ownerEmail === req.userEmail) is
      GONE. The new authorization check for an embedded call:
        - req.shopDomain (from the verified token's `dest`) ===
          req.params.shopDomain  -> the merchant is authenticated
          by Shopify AS that shop's admin, so a matching shop is
          sufficient authz.
        - Store.findOne({ shopDomain }) still required (must be an
          installed store) -> 404 if missing.
        - Drop the "no ownerEmail" 403 branch for this path
          (ownerEmail stays relevant only to the NextAuth
          /dashboard).
      Set req.store as before.
  (5) requirePaidPlan is unaffected (reads req.store.plan) — still
      dormant.

  DUAL-FLOW CONSIDERATION:
    The 15 protected routes are shared by BOTH the NextAuth
    /dashboard UI (BACKEND_JWT_SECRET JWT, email-based) and the
    embedded /admin UI (Shopify session token, shop-based). If
    both must keep working, requireAuth needs to try BOTH:
      - first jwt.verify(token, SHOPIFY_API_SECRET) + aud/iss
        checks -> session-token path (set req.shopDomain), else
      - jwt.verify(token, BACKEND_JWT_SECRET) -> NextAuth path
        (set req.userEmail),
    and requireStoreOwner authorizes if EITHER
    (req.shopDomain === params.shopDomain) OR
    (store.ownerEmail === req.userEmail).
    If /dashboard is being retired in favour of /admin, the
    BACKEND_JWT_SECRET path (and /api/token, and the frontend
    `jsonwebtoken` dep) can all be deleted.

    - No new app-level middleware ordering issue — requireAuth is
