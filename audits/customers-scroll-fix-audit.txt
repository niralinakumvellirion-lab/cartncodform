FIX 1 — Left panel container
====================================================================
Applied minWidth: 0 and overflow: 'hidden' to the OUTER wrapper div
(the direct child of the 2-panel CSS Grid, previously a bare
`<div>` with no style at all) rather than the inner card div one
level down. This distinction matters: the outer wrapper is the
actual CSS Grid ITEM here — grid items default to `min-width: auto`,
which is exactly the browser behavior the task's own comment
describes ("without minWidth: 0, CSS grid children don't shrink
below their content size"), so this had to go on the grid item
itself to have any effect. The inner `...DS.card` div is a normal
block child of that wrapper, not a grid item, so putting minWidth:0
there instead would not have addressed the actual grid-shrinking
behavior.

NOTE on how this interacts with the PREVIOUS task's fix (see
audits/customers-columns-fix-audit.txt): that task deliberately gave
the INNER card div its own `minWidth: 600` + `overflowX: 'auto'`, so
the cramped 6-column table could scroll horizontally within itself
on narrow viewports instead of squishing. This task's new outer
wrapper now has `minWidth: 0` + `overflow: 'hidden'`. These are NOT
in conflict — this is the standard nested-overflow pattern for
exactly this situation: the outer grid item shrinks to fit its
allotted grid track (minWidth: 0) and clips anything that doesn't
fit (overflow: hidden), while the inner card still provides its own
scrollable viewport (overflowX: auto) for the wider table content
inside that clipped boundary. The net effect: the customer list's
own internal table can still be scrolled horizontally to see all 6
columns on a narrow screen, but that scrolling stays CONTAINED
within the left panel's card — it no longer forces the whole page
(or the 2-panel grid) to overflow horizontally. This is exactly what
this task's title asks for ("no horizontal scroll" at the page level,
while the previous task's own internal-table-scroll fix is
preserved).
