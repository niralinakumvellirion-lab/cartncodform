=== HOW THE SCREEN CAN READ shopName / primaryColor / logoUrl ===

GET /api/profiles/:shopDomain/settings (backend/routes/profiles.js:629)
returns: { voice, caps, quietHours, timezone, shopName, logoUrl, primaryColor }
This is already used by Settings.jsx (apiGet(`/api/profiles/${shop}/settings`)).
shopDomain can be read from window.shopify.config.shop (App Bridge) or from
the server-rendered shop param on /admin routes; Settings.jsx reads it via
the backend — a GET /api/settings or /api/profiles/:shop/settings call.

Alternative: read it from the store returned in the emailTemplates response
(the backend loadBrandData helper returns it internally but does not expose it
in any list/GET /template response). The front-end must call /api/profiles/:shop/settings
or extract the shopDomain from the auth token to read brand data directly.

For E3a the simplest path is: on screen load, call
  GET /api/profiles/${shopDomain}/settings
and store { shopName, logoUrl, primaryColor }. The shopDomain can be taken from
the App Bridge window.shopify.config.shop (available when App Bridge is loaded).

=== CSP / HEADERS (next.config.js) ===

next.config.js sets one header for /admin/:path*:
  Content-Security-Policy: frame-ancestors https://admin.shopify.com https://*.myshopify.com

This header restricts who can embed the admin in an iframe.
It does NOT set a restrictive CSP for script-src, font-src, img-src, etc.
Therefore:
  - fonts.googleapis.com  → NOT blocked (no font-src restriction)
  - fonts.gstatic.com     → NOT blocked
  - data: images          → NOT blocked (no img-src restriction)
  - Google Fonts <link>   → safe to add in a useEffect or in the iframe's srcdoc
No new CSP problems with E3a's requirements.

=== POST /api/email-templates/photo CONTRACT ===

Location: backend/routes/emailTemplates.js (declared BEFORE /:id routes)
Auth: requireAuth (shopDomain scoped), photoRateLimiter (20/hour per shop)
Body: express.json({ limit: '11mb' }) (route-scoped; note: global limit is 10mb
      so effective max is ~10mb at the Express layer — safe ceiling is 7 MB binary)

Request:  POST /api/email-templates/photo
          { dataUrl: "data:image/jpeg;base64,..." }
          Only image/jpeg, image/png, image/webp accepted.
          Decoded size must be <= 8 MB (frontend should cap at 7 MB for safety).

Responses:
  200 { url: string, width: number, height: number }  — Cloudinary URL + dimensions
  400 { error: "dataUrl is required" }
  400 { error: "Only JPEG, PNG, or WebP images are accepted" }
  413 { error: "Image is too large. Maximum size is 8 MB." }
  503 { error: "Photo upload is not configured" }   — Cloudinary env missing
  502 { error: "Photo upload failed. Try again." }  — Cloudinary upload failed
