2. VERDICT PER CONTROL
────────────────────────────────────────────────────────────────

Rule: 5+ options OR confirmed horizontal scroll → dropdown.
      2-4 short options that always fit in practice → stay as pills.

A. Customers segment filter   → DROPDOWN
   Reason: 7 options + confirmed overflow.

B. Messages channel filter    → STAY AS PILLS
   Reason: 4 options; actual scroll does not fire at typical admin widths.
   Note: "Led to a sale" is the longest label (13 chars). If the admin is
   ever rendered narrower than ~350px (rare), overflow kicks in, but that
   is below the minimum Shopify iframe width.

C. Journey signal type filter → DROPDOWN
   Reason: 5 options + confirmed overflow (emoji labels widen each pill).

D. Queue status filter        → STAY AS PILLS
   Reason: 3 short options, no actual overflow.

E. CustomerDetail timeline    → STAY AS PILLS
   Reason: 3 short options, no overflow container, right-aligned header group.

5. SHARED COMPONENT? WHAT WOULD IT NEED?
────────────────────────────────────────────────────────────────

No shared filter component exists today. DateRangeFilter.jsx covers date
pickers only. Every other filter is hand-rolled inline with its own
.map() over a local FILTER_TABS or inline array.

A shared <FilterDropdown> component would need:

  props:
    options     — array of { key, label }
    value       — currently selected key
    onChange    — (key) => void
    label?      — accessible <label> for the <select> (e.g. "Filter by")
    style?      — escape hatch for margin/width overrides

  behaviour:
    - Renders a native <select> matching the SelectRow styling in Settings.jsx
      (border #e5e7eb, borderRadius 6, bg #fff, padding 5px 8px, fontSize 12)
    - Reflects an incoming URL-seeded value on mount (callers already handle
      this via their useState initialiser — component just needs a controlled
      value prop)
    - No multi-select needed (all three current use cases are single-select)
    - No "All" injection needed — callers already include an "All/Everyone"
      option in their arrays

  file suggestion: frontend/app/admin/components/FilterDropdown.jsx
