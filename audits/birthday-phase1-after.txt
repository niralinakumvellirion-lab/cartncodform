2. FILES CHANGED + WHAT CHANGED
═══════════════════════════════════════════════════════════

backend/models/Profile.js
  Added `birthday` sub-doc: month (1-12), day (1-31), capturedAt (Date),
  source (String). Absent by default (all default: null). No index needed.

backend/models/DiscountConfig.js
  Added `birthdayCapture.popup.enabled` (Boolean, default false).
  Added `birthdayDiscount`: enabled, percentage (0-100, default 15),
  expiryDays (1-30, default 7), prefix (String, default 'BDAY'), offerText.

backend/routes/discounts.js (defaultConfig + PATCH handler)
  defaultConfig(): added birthdayCapture and birthdayDiscount back-compat defaults.
  PATCH handler: accepts birthdayCapture.popup.enabled (Boolean guard),
  birthdayDiscount.enabled/percentage (clamped 0-100)/expiryDays (clamped 1-30)/
  prefix (sanitized: uppercase, alphanumeric only, ≤10 chars, falls back to 'BDAY')/
  offerText (trimmed, ≤120 chars). Same sanitization style as existing rules.

backend/routes/proxy.js
  GET /discount-config: now also returns birthdayCapture.popup.enabled,
  birthdayDiscount.percentage, and birthdayDiscount.offerText (the three
  fields the storefront needs). Never returns `enabled` from birthdayDiscount
  (not relevant to storefront — no offer is sent in Phase 1).

  POST /birthday (new): App Proxy signature required. Rate-limited: 5/min per
  ip|shop|sessionId key (generous enough for any real visitor, blocks abuse).
  Rejects when birthdayCapture.popup.enabled is false. Validates month/day as
  a real calendar day; Feb 29 allowed (leap-year birthdays). On success: calls
  upsertProfile(shop, { sessionId }, { birthday.month, birthday.day,
  birthday.capturedAt, birthday.source: 'popup', lastSeenAt }). Returns
  { ok: true }. Never logs month or day values.

backend/routes/webhooks.js
  Updated comment in customers/redact to say "birthday/WhatsApp" since both
  are now sub-docs deleted when Profile.deleteMany runs.

extensions/cartncodform-embed/assets/ccf-push.js
  Added module-level function `ccfShowBirthdayStep(wrap, accentColor, onDone)`.
  Checks discountConfig.birthdayCapture.popup.enabled and localStorage key
  ccf_bday_<SHOP_DOMAIN>; if either says skip, calls onDone() immediately.
  Replaces #ccf-content-section content with: offerText headline, consent line,
  month <select> (named months, value 0 = placeholder), day <select> (1-31),
  "Save my birthday" button, "Skip" button, inline error div. Accessible
  aria-label on both selects. Month select uses named months (not numbers);
  day select is 1-31. On save: fetches /apps/cartncodform/birthday, then
  calls markDone(true) → localStorage ccf_bday_=1 → onDone(). On error:
  markDone(true) anyway (failure never blocks). On skip: localStorage
  ccf_bday_=skip → onDone(). Try/catch around entire function body — any
  unexpected error calls onDone() safely.

  Hooked into 4 success paths inside showSoftPrompt:
    a. No-discount subscribe: was setTimeout(cleanup, 900) → now
       ccfShowBirthdayStep(wrap, accent, cleanup)
    b. Normal subscribe with discount: finishDiscount(d, action) →
       ccfShowBirthdayStep(wrap, accent, () => finishDiscount(d, action))
    c. Already-subscribed (granted path): finishDiscount(d, capAction) →
       ccfShowBirthdayStep(wrap, accent, () => finishDiscount(d, capAction))
    d. offerBtn email path: finishDiscount(d, 'email') →
       ccfShowBirthdayStep(wrap, accent, () => finishDiscount(d, 'email'))
  WhatsApp offerBtn (setTimeout(cleanup, 2500)) left unchanged — that path
  already has its own success card and 2.5s auto-close.

frontend/app/admin/screens/Discounts.jsx
  buildPayload(): added birthdayCapture and birthdayDiscount to the payload
  sent to PATCH /api/discounts/:shop/config.
  UI: Added "Birthday offer" card after the WhatsApp card (before Save button).
  Card has: gift icon, title "Birthday offer", toggle (same green switch style
  as WhatsApp). When toggle is ON: shows offer text field (≤120 chars),
  percentage input (0-100), validity days (1-30), code prefix (≤10 chars).
  Helper text: "Birthdays are collected and stored now. Offers are sent starting
  in the next release." (amber/warning color). No Pro gating — Free/Pro applies
  at sending time (not yet implemented); collection itself is free to configure.

═══════════════════════════════════════════════════════════

backend/routes/proxy.js:261 — upsertProfile(shop, { sessionId }, updates)
  Reuses the existing profileService.js upsertProfile(). Identity resolved by
  sessionId (stable localStorage UUID). If the profile doesn't exist yet, it
  is created; if multiple sessions merged into one profile, the birthday is
  written to the winning (highest-priority) profile. Same logic as the
  whatsapp capture path (proxy.js lines 455-456, 546-547 pre-birthday).
