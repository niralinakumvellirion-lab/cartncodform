WHY `shopify app deploy --allow-updates` WAS NOT RUN
====================================================================

This command would register the new-domain URLs above with
Shopify's LIVE platform configuration for the real installed app —
not a local/git-reversible action. Once deployed, Shopify starts
sending:
  - OAuth install/reinstall callbacks to api.shopireachboost.com
  - All 4 webhook deliveries (including the 3 GDPR-mandatory
    compliance topics) to api.shopireachboost.com
  - Every App Proxy request from the live storefront (the push-
    notification prompt, automatic discount-code generation, and the
    Cash-on-Delivery order form — all served through
    extensions/cartncodform-embed/blocks/push-notifications.liquid's
    App Proxy calls) to api.shopireachboost.com

Earlier this session, when asked directly whether
api.shopireachboost.com / app.shopireachboost.com / Resend are fully
live, the user's explicit answer was "Not yet — hold off on
deploying," with instructions to apply code changes but not push/
deploy them (see audits/domain-migration-audit.txt and
audits/ui-redesign-audit.txt for how the subsequent git push /
Vercel deploy were scoped around that answer). Nothing since then
has confirmed the backend/Render side is actually reachable at
api.shopireachboost.com — a Vercel alias for app.shopireachboost.com
was found to already exist (audits/ui-redesign-audit.txt), but that
says nothing about whether Render has a matching custom domain
configured for the backend.

If api.shopireachboost.com does not yet resolve to the live Render
backend, running this deploy would immediately break: OAuth install/
reinstall (Shopify would redirect to a domain the backend may not be
reachable at), all webhook delivery including GDPR compliance
webhooks, and — most visibly to real customers — the storefront App
Proxy, meaning the push-notification prompt, discount codes, and the
COD order form would all stop working on the live store the moment
this deploy completes. Unlike the git push handled in the previous
task, there is no side-branch/partial-push equivalent available here
— `shopify app deploy` either changes Shopify's live routing now, or
it doesn't; there's no way to apply it "for later" without affecting
the live app immediately.

Given the user's own explicit, still-unretracted "not yet" answer on
domain readiness, running this deploy now would directly contradict
that instruction and risk breaking live storefront functionality for
the real merchant. Declined to run it. Ready to run
`shopify app deploy --allow-updates` as soon as the user confirms
api.shopireachboost.com is actually live and reachable on Render.
