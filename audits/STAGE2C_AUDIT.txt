LOGIC ADAPTED BEYOND JSX (and why)
================================================================
  #1  `disconnecting` state REMOVED.
      WHY: it was read only by handleDisconnect (to guard re-entry)
      and by the Disconnect button (disabled + label). Both are
      dropped by decision [1]. Keeping the useState would be an
      unused variable (dead code + eslint no-unused-vars). This is
      a direct consequence of the DROP, not a separate change.

  #2  `shop`: `const shop = decodeURIComponent(params.shop || '')`
      -> `function StoreView({ shop })` (prop).
      WHY: decision [1]/[4] — the embedded /admin route has no
      dynamic path segment; shop is a query param read via
      useSearchParams in AdminHomeContent and passed down. No
      useParams. The value semantics are the same (a shop-domain
      string); the source's decodeURIComponent is not needed
      because searchParams.get() already returns a decoded value.

  #3  Tab state <-> Polaris <Tabs> index mapping.
      SOURCE: `tab` is a string ('abandoned'|'cod'|'automation');
      hand-rolled tabButton(key,...) calls setTab(key).
      PORTED: `tab` state + its useState('abandoned') initializer
      are UNCHANGED. Added:
        const tabs = [
          { id: 'abandoned',  content: `Abandoned Carts (${customers.length})`, panelID: 'abandoned-panel' },
          { id: 'cod',        content: `COD Orders (${orders.length})`,        panelID: 'cod-panel' },
          { id: 'automation', content: 'Automations',                          panelID: 'automation-panel' },
        ];
        const selectedTab = Math.max(0, tabs.findIndex((t) => t.id === tab));
      and `<Tabs tabs={tabs} selected={selectedTab}
        onSelect={(idx) => setTab(tabs[idx].id)}>`.
      WHY: Polaris <Tabs> is index-driven (selected: number,
      onSelect(index)); the source's string state is preserved and
      just bridged to/from the index. The count-in-label logic
      matches the source's tabButton (append "(count)" for
      abandoned/cod; none for automation, which passed count=null).

  #4  COD status <select> -> Polaris <Select>.
      SOURCE: `<select value={o.status} onChange={(e) =>
        updateOrderStatus(o._id, e.target.value)}>` with three
        <option>s: pending / confirmed / cancelled.
      PORTED: `<Select label="Status" labelHidden
        options={COD_STATUS_OPTIONS} value={o.status}
        onChange={(value) => updateOrderStatus(o._id, value)} />`
      where COD_STATUS_OPTIONS is a module-level const
        [{label:'pending',value:'pending'}, {..'confirmed'..}, {..'cancelled'..}]
      built from the distinct status strings the source used.
      WHY: Polaris <Select> onChange passes the selected VALUE
      string (verified in the installed d.ts:
      `onChange?(selected: string, id: string)`), not a DOM event
      — so `e.target.value` becomes `value`. `updateOrderStatus`
      itself is untouched.

  #5  CustomerAnalytics: mount-gate -> always-mounted + `open`.
      SOURCE: `{analyticsCustomer && <CustomerAnalytics shop=...
        customer=... onClose=... />}` (conditionally MOUNTED).
      PORTED (per decision): `<CustomerAnalytics
        open={!!analyticsCustomer} shop={shop}
        customer={analyticsCustomer}
        onClose={() => setAnalyticsCustomer(null)} />` — rendered
      unconditionally; the ported CustomerAnalytics (Stage 2b)
      already expects `open` for its Polaris <Modal>.
      `shop={shop}` is passed even though the decision text listed
      only open/customer/onClose — CustomerAnalytics needs `shop`
      to build its /api/events URLs; omitting it would break the
      fetch.

  #6  Error box -> Polaris <Banner>.
      SOURCE: a red <div> with <p className="font-medium">Couldn't
      load store data</p> + <p>{error}</p> + a "Try again"
      <button onClick={load}>.
      PORTED: `<Banner tone="critical" title="Couldn't load store
      data" action={{ content: 'Try again', onAction: load }}>
      <Text as="p">{error}</Text></Banner>`. The "Try again" button
      is now the Banner's `action`. (Minor: the heading apostrophe
      is a straight ' — the source may have used a curly ’; purely
      cosmetic.)

  #7  Loading indicator -> Polaris <Spinner>.
      SOURCE: a pulsing dot <span className="animate-pulse ..."/> +
      "Loading store data…".
      PORTED: `<InlineStack gap="200" blockAlign="center"><Spinner
      accessibilityLabel="Loading store data" size="small" /><Text
      as="span" tone="subdued">Loading store data…</Text></InlineStack>`.

  #8  Sibling order around <Tabs>.
      SOURCE flat order: tab strip, then error box, then loading
      indicator, then the panels.
      PORTED: RevenueStats, then error <Banner>, then loading
      <Spinner>, then `<Tabs>` whose CHILDREN are the three panels.
      WHY: Polaris <Tabs> renders its children as the tab panel, so
      the non-tab-specific error/loading rows had to move above
      <Tabs> rather than sit between the strip and the panels.
      Functionally identical; the panels keep their exact gates:
        {!loading && tab === 'abandoned' && <IndexTable .../>}
        {!loading && tab === 'cod' && <IndexTable .../>}
        {tab === 'automation' && <AutomationRules shop={shop} />}   (NOT loading-gated, matches source)

  #9  Page header -> Polaris <Page>.
      SOURCE: a custom flex <div> with <h1>{shop}</h1> + a
      "Abandoned carts & COD orders" <p> + Refresh + Disconnect
      buttons.
      PORTED: `<Page title={shop} subtitle="Abandoned carts & COD
      orders" secondaryActions={[{ content: 'Refresh', onAction:
      load }]}>`. Disconnect dropped (decision 1). StoreView now
      OWNS the <Page> (AdminHomeContent no longer renders one).

  #10 The two <table>s -> Polaris <IndexTable>.
      - `<table>/<thead>/<tbody>` -> `<IndexTable itemCount=...
        selectable={false} headings={[{title:'...'}, ...]}>`.
      - each `<tr>` -> `<IndexTable.Row id=... key=... position=...>`;
        the abandoned-carts row keeps `onClick={() =>
        setAnalyticsCustomer(c)}` (COD rows have no onClick, same as
        source).
      - each `<td>` -> `<IndexTable.Cell>`.
      - the "No abandoned carts yet." / "No COD orders yet."
        full-width empty <tr> -> the IndexTable `emptyState` prop
        (renders when itemCount === 0).
      - the `<div onClick={(e) => e.stopPropagation()}>` wrappers
        around SendPushButton and WhatsAppButton are PRESERVED
        verbatim from the source (so an action click doesn't also
        fire the row's open-analytics onClick — standard React
        bubble-stop, still valid inside IndexTable.Row).
      - cell inner text/markup: Tailwind <span>/<p> -> <Text as=
        "span"> (with tone="subdued" / fontWeight="medium" /
        truncate as the source's classes implied); the item list
        column uses <BlockStack>/<InlineStack>.
      - VERIFIED in the installed Polaris 13.9.5 that <IndexTable>
        wraps itself in <IndexProvider> internally (no separate
        provider needed) and works standalone with selectable=false.

  #11 AdminHomeContent trimmed.
      - `host` (searchParams.get('host')) extraction REMOVED — it
        was only shown in the deleted placeholder card; keeping it
        would be an unused var. (App Bridge reads host from the URL
        + the shopify-api-key meta itself.)
      - The placeholder <Card> and the "Component Preview
        (temporary)" <Card> are REMOVED entirely.
      - The `<Page title="CartnCodForm"><BlockStack>...</BlockStack>
        </Page>` wrappers are REMOVED — StoreView provides its own
        <Page>.
      - Return is now: <> <meta shopify-api-key> <Script app-bridge>
        <AppProvider i18n={{}}> <StoreView shop={shop} /> </AppProvider> </>.

  NOT CHANGED: load(), updateOrderStatus(), every WhatsApp/COD
  message template literal (byte-for-byte), and every
  already-ported child component (formatMoney/formatDate/
  StatusBadge/SendPushButton/WhatsAppButton/RevenueStats/
  CustomerAnalytics/StepEditor/RuleForm/AutomationRules) — those
  files' regions were not touched. `export default function
  AdminHome()` (the <Suspense> wrapper) — untouched.
