  Notes (observations only):
  * Uses <Page title="Today"> + <Layout> — a Polaris page wrapper. Since the
    admin shell dropped the Frame (page.js), this renders bare, no app chrome.
  * Fetches 3 endpoints in parallel via Promise.allSettled:
      GET /api/profiles/:shop/weekly-narrative   -> narrative, insights[], stats
      GET /api/profiles/:shop/push-stats         -> pushStats tile
      GET /api/profiles/:shop/signals?limit=3    -> "What to act on" list
    Error is only surfaced when ALL THREE reject; a partial failure shows
    em-dashes / empty states silently.
  * 6 sections: This week (narrative) · 4 stat tiles · Push delivery
    (oneThird) · What to act on (top 3 signals) · Insights (bulleted).
  * Stat tiles read stats.profilesLookedAt / messagesSent / conversions /
    revenueRecovered — these match analyticsService.computeWeeklyStats()'s
    return keys exactly (profilesLookedAt, messagesSent, conversions,
    revenueRecovered, topProduct, bestChannel). topProduct / bestChannel are
    returned but NOT shown on this screen.
  * Signal rows key on sig._id and render sig.type, sig.evidence[0],
    sig.strength (0..1, shown as %). Badge tone thresholds: >0.7 critical,
    >0.4 warning, else info.
  * "Recovered" tile label vs. value: labelled "Recovered", shows
    stats.conversions (recovered-cart count).
  * No refresh control, no date-range control, no auto-poll — one fetch per
    shop change.

 21	/**
 22	 * GET /api/profiles/:shopDomain/signals
 23	 * Query: type (optional), limit (default 20, max 100)
 24	 * -> { signals: [...] }  strongest first
 25	 */
 26	router.get('/:shopDomain/signals', requireAuth, requireStoreOwner, async (req, res) => {
 27	  try {
 28	    const shop = req.params.shopDomain.trim().toLowerCase();
 29
 30	    let limit = parseInt(req.query.limit, 10);
 31	    if (!Number.isFinite(limit) || limit < 1) limit = 20;
 32	    if (limit > 100) limit = 100;
 33
 34	    const filter = { shopDomain: shop };
 35	    if (req.query.type) filter.type = req.query.type;
 36
 37	    const signals = await Signal.find(filter)
 38	      .sort({ strength: -1 })
 39	      .limit(limit)
 40	      .populate('profileId', 'identifiers stage');
 41
 42	    return res.json({ signals });
 43	  } catch (err) {
 44	    console.error('[profiles] GET signals error:', err.message);
 45	    return res.status(500).json({ error: 'Failed to fetch signals' });
 46	  }
 47	});

--- 2b. GET /:shopDomain/weekly-narrative  (lines 254-286) -------------

254	/**
255	 * GET /api/profiles/:shopDomain/weekly-narrative
256	 * -> { narrative, insights: [string], stats }
257	 * The full computation is cached in-process for 1 hour per shop so an admin
258	 * page load does not re-run aggregations + LLM calls every time.
259	 */
260	const narrativeCache = new Map(); // shopDomain -> { at: ms, data }
261	const NARRATIVE_TTL = 60 * 60 * 1000;
262
263	router.get('/:shopDomain/weekly-narrative', requireAuth, requireStoreOwner, async (req, res) => {
264	  try {
265	    const shop = req.params.shopDomain.trim().toLowerCase();
266
267	    const cached = narrativeCache.get(shop);
268	    if (cached && Date.now() - cached.at < NARRATIVE_TTL) {
269	      return res.json(cached.data);
270	    }
271
272	    const stats = await computeWeeklyStats(shop);
273	    const rawInsights = await computeInsights(shop);
274	    const [narrative, insights] = await Promise.all([
275	      generateWeeklyNarrative(shop, stats),
276	      generateInsights(shop, rawInsights),
277	    ]);
278
279	    const data = { narrative, insights, stats };
280	    narrativeCache.set(shop, { at: Date.now(), data });
281	    return res.json(data);
282	  } catch (err) {
283	    console.error('[profiles] GET weekly-narrative error:', err.message);
284	    return res.status(500).json({ error: 'Failed to build weekly narrative' });
285	  }
286	});

  Notes (observations only):
  * Both routes: requireAuth + requireStoreOwner, scoped by :shopDomain
    (trimmed + lowercased), never by email.
  * signals: Signal model queried with `(filter)` then chained
    `.sort({ strength: -1 }).limit(limit).populate('profileId', ...)`.
    Response is `{ signals }` — the raw docs (with populated profileId).
    Today.jsx reads sig._id / sig.type / sig.strength / sig.evidence[]
    from these; it does NOT use the populated profileId.
  * weekly-narrative: in-process Map cache, 1-hour TTL, per shopDomain.
    Cache is module-level → shared across requests, lost on process restart,
    and NOT invalidated here (PATCH /settings elsewhere does
    `narrativeCache.delete(shop)` on a voice change).
  * `stats` in the response is computeWeeklyStats(shop) verbatim
    (deterministic; the LLM only narrates). Keys: profilesLookedAt,
    messagesSent, conversions, revenueRecovered, topProduct, bestChannel.
  * `insights` is generateInsights(shop, computeInsights(shop)) — an array
    of strings. computeInsights uses a 30-day window; computeWeeklyStats
    uses 7 days.
  * generateWeeklyNarrative / generateInsights come from aiService; they
    fall back to deterministic text when LLM_API_KEY is unset (per earlier
    audits, it is unset in Render).
