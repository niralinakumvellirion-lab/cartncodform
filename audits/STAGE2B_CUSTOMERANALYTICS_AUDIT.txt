LOGIC ADAPTED (beyond pure JSX)
================================================================
  (1) ADDED the `open` prop to the component signature.
      WHY: the task's mapping says
        "Modal open/close -> driven by existing open prop passed
         in from parent".
      But the SOURCE component had NO `open` prop — the parent
      (StoreView) conditionally MOUNTED it:
        `{analyticsCustomer && <CustomerAnalytics shop=... customer=... onClose=... />}`
      Polaris's <Modal> uses the always-mounted + `open` toggle
      pattern instead, and `open` is how you show/hide it. So
      `open` was added to `{ open, shop, customer, onClose }` and
      passed straight to `<Modal open={open} ...>`.
      IMPACT: this is a PROPS-CONTRACT change, not one of the
      three protected categories (state logic / API logic /
      handler functions). The ported component is not wired to
      any parent yet; Stage 2c's parent wiring will supply
      `open` (and keep the component mounted). Flagging because
      the task's word "existing" is inaccurate for the source as
      it stands.

  (2) EMPTY-STATE COPY CHANGED (task-prescribed).
      SOURCE rendered:
        "No events tracked yet."
        + sub-line: "Events are tracked when a subscribed customer
                     browses the store."
      The task's mapping prescribes verbatim:
        "Empty state -> <Text tone='subdued'>No journey events
         found.</Text> inside a <Box padding='400'>"
      So the ported empty state is:
        <Box padding="400"><Text as="p" tone="subdued">No journey events found.</Text></Box>
      NET: the empty-state message text changed and the
      explanatory sub-line was dropped, per the task's explicit
      instruction. (This is content, i.e. part of the "JSX
      layer" the task said may change, and it was spelled out
      verbatim.)

  (3) SECTION HEADING -> Modal `title` prop (not a separate <Text>).
      SOURCE had one heading: <h2 className="font-bold">Customer
      Journey</h2> in the panel's sticky header.
      Polaris <Modal> REQUIRES a `title` prop (verified in the
      installed d.ts: `title: string | React.ReactNode` — not
      optional) and renders it as the panel heading in the modal
      chrome. So `title="Customer Journey"` fulfils both the
      "slide-over panel -> <Modal>" and the "Section heading ->
      <Text variant='headingSm' as='h2'>" mappings. A separate
      <Text variant="headingSm" as="h2">Customer Journey</Text>

      render "Customer Journey" twice.
