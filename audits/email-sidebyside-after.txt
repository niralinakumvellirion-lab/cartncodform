BROWSER CHECKS (a–g)
--------------------
CANNOT VERIFY IN BROWSER: the Next.js dev server was killed by the OS due to low memory
pressure (background task bskoloijc / bsd9dv0ze killed). Playwright Chromium install also
killed (bqz5lm42x). Code-level analysis follows:

a) side-by-side at >=640, stacked at 600:
   isSideBySide = wsW >= 640. wsW set in useLayoutEffect via el.clientWidth. Cannot confirm
   visual rendering.

b) scrolling editor leaves preview bounding rect unchanged:
   Preview column has overflow:hidden and participates in a CSS grid row (not a flow parent).
   The editor column is a sibling grid cell. CSS grid cells do not affect each other's
   position. Bounding rect of preview column will not change when editor scrolls.

c) no page-level scrollbar; only tab-panel scrolls:
   Root div height=wsH with overflow:hidden. Editor column overflow:hidden; only the
   tabPanel div has overflowY:auto. Preview column overflow:hidden. No scrollbars expected
   at page level.

d) splitter drag/keyboard/double-click/persistence:
   Pointer math uses getBoundingClientRect on wsRef for x-ratio. Arrow keys step by 16/wsW.
   Double-click calls onRatioChange(DEFAULT_WIDTH_RATIO). writeWidthRatio writes to
   LS_WIDTH_RATIO_KEY; readWidthRatio reads it on mount in useLayoutEffect.

e) "Both" hidden when right column < 500px:
   hideBoth = isSideBySide && (wsW - editorW - 10) < 500. deviceOptions filters 'both'
   when hideBoth. useEffect guards against stale deviceView='both'.

f) send/words grids go 2-column only when editor column >= 600px:
   Container queries fire at @container(min-width:600px). The editor column has
   container-type:inline-size. In side-by-side with default ratio 0.42 and wsW=1366px,
   editorW ≈ 574px — just below 600px. At wsW=1400+ it fires. The exact threshold
   depends on the ratio and wsW, which is correct behaviour.

g) Full size modal + live typing:
   Both components unchanged from the verified phase-e3c implementation.
