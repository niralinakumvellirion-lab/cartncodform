--- Fallback when no row matches ---
Lines 124-144: if `cartSubs.length === 0` (no live subscription row
for this exact cartToken -- e.g. it was overwritten by a resync, as
explained in this file's own comment at lines 114-123), it re-

`profile.identifiers.cartTokens`, which accumulates every cartToken

Same sort: most-recently-active row first, but now matching ANY of
that profile's historical cartTokens, not just the one originally

--- Selecting which subscription to actually use ---
Lines 146-188: NOT a single "pick the top row" selection -- it
loops through every row in `cartSubs` (already sorted most-recent-
first) and tries sending to each ONE AT A TIME until one succeeds:
  for (const sub of cartSubs) {
    ... build message with tokens: [sub.token] ...
    const response = await getMessaging().sendEachForMulticast(message);
    const result = response.responses[0];
    if (result.success) {
      return { success: true, sent: 1, tokensFound: cartSubs.length };
    }
    const code = result.error?.code || '';
    if (isStaleCode(code)) {
      await handleStaleToken(sub.token, shop);
      console.log(`[push-customer] Stale token pruned, trying next...`);
    } else {
      console.error(`[push-customer] token FAILED: ${code || result.error?.message}`);
      break;
    }
  }
So: try the most-recently-active row's token first; if it sends
successfully, stop and return immediately (1 device gets the
notification, not all of them). If it fails with a STALE token
code (per isStaleCode() from services/pushHygiene), prune that
token (delete the subscription + related profile bookkeeping) and
move on to the NEXT most-recently-active row. If it fails with any
OTHER (non-stale) error, stop trying entirely (`break`) rather than
continuing down the list -- a real, unrecoverable send error on one
device is treated as a reason to give up on this cartToken rather
than trying an older device.

If every row is exhausted without a successful send (either the
loop finishes naturally or `cartSubs` was empty even after the
fallback), it returns without sending:
  console.log(`[push-customer] cartToken: no valid token found for cart ${cartToken} — skipping`);
  return { success: true, sent: 0, tokensFound: 0 };
Note this returns success: true even when nothing was sent (0
sent) -- distinguishing "no push subscription available for this
customer" from "sending failed" (only the outer catch block, or the
`break` case where a non-stale error stopped the loop but the
function still returns this same success:true/sent:0 shape either
way -- the specific error reason for that terminal failed attempt
is only visible in the console.error log, not returned to the
caller).
