5. SendEmailButton — component exists with correct props / state / handler
================================================================================
CONFIRMED. Added directly AFTER SendPushButton, before StatusBadge.

  Props:  { shop, sessionId, cartToken }
          (cartToken accepted per spec; the send uses `sessionId` as the
           cartToken value sent to the backend, matching the spec's handler.)
  State:  active         (Popover open/closed)
          emailSubject   (Subject TextField)
          emailBody      (Message TextField, multiline={2})
          sending        (button loading/disabled)
  UI:     <Button>✉️ Email</Button> activator -> <Popover> containing a <Card>
          + <FormLayout> with Subject TextField, Message TextField
          (multiline={2}), and an <InlineStack gap="200"> holding
          "Send" (variant="primary") and "Cancel" (variant="plain").
  Handler (sendEmail): matches the spec's body exactly —
          setSending(true) -> apiSend('/api/push/send-email-test', ...,
          { shopDomain: shop, cartToken: sessionId, subject: emailSubject,
            body: emailBody }) -> on success setActive(false) + clear both
          fields -> catch logs '[email] send-email-test failed:' ->
          finally setSending(false).

DEVIATION (required): the spec snippet calls
  apiSend(path, { ...body }, 'POST')
but this codebase's helper signature is `apiSend(path, method, body)` (see
frontend/lib/api.js:74 and every other call site, e.g. SendPushButton's
`apiSend('/api/push/send-customer', 'POST', {...})`). Implemented as
  apiSend('/api/push/send-email-test', 'POST', { shopDomain, cartToken,
          subject, body })
Using the spec's literal argument order would pass the body object as
`method` and the string 'POST' as `body`, producing a broken request.
Everything else (endpoint, payload keys, control flow) is per spec.

Note: Popover activator click and the Cancel click both call
`e.stopPropagation()` so opening/closing the email composer does not trigger
the row's `onClick` (which opens the Customer Journey modal) — same guarding
SendPushButton already uses.
