1. The 1 MB file guard uses `dataUri.length > MAX_PHOTO_BYTES * 1.37`.
   Base64 encodes 3 bytes as 4 chars (×4/3 ≈ 1.333), plus the `data:image/…;
   base64,` prefix (~30 chars). The factor 1.37 gives ~3% headroom. A real
   browser test would confirm the exact threshold on a 1.0 MB vs 1.05 MB file.

2. The Mobile/Desktop preview image renders at `aspectRatio: '2/1'` — cannot
   verify the exact pixel layout or that object-fit cover works as expected
   without a browser.

3. Audience radio cards: `role="radio"` + `aria-checked` are set but keyboard
   navigation (arrow keys to move between options) is not implemented —
   only click. Full ARIA 1.1 radiogroup pattern requires keyboard handling;
   the spec said to add the roles which is done.

4. The email segment count fetch hits
   `/api/email-templates/${shop}/count?segment=X`. The route is
   GET /api/email-templates/count?segment=X — the shop comes from
   requireAuth's req.shopDomain. The frontend path includes shop in the URL
   (as the existing email-templates list endpoint does) but the count route
   does not actually use it as a URL param — requireAuth sets shopDomain from
   the session token. This is consistent with how every other admin call works
   and is not a bug; verified against emailTemplates.js line 204-218.

5. Push-subscriber-count: the "About N customers" on the audience header
   shows pushSubscriberCount?.total. The fetch only fires the first time the
   push channel is opened per session (guarded by `pushSubscriberCount === null`).
   This is intentional — same pattern as email segment counts.
