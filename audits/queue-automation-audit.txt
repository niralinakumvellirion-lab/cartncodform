Exactly one sort key: `createdAt: -1` -- descending by the document's
own creation timestamp (ScheduledJob has `{ timestamps: true }` in its
schema, so `createdAt` is Mongoose-managed, set once when the job row
is inserted and never changed again). This means the list is ordered
by "when this job was SCHEDULED/CREATED", not by `runAt` (when it's
due/was due to run), not by `status`, and not by `updatedAt` (which
WOULD move whenever a job's status changes, e.g. via the send-now/
cancel actions in this same file) -- a job created earlier always
sorts above one created later, regardless of which one is due sooner
or which one was most recently acted on.
`limit` is hardcoded to 20 (line 15, `const limit = 20;`) -- not
configurable via any query param; `page` (from `req.query.page`,
defaulting to '0') drives `.skip(page * limit)`.
This is the ONLY sort/pagination logic in the file -- the two POST
action routes (send-now, cancel) don't sort anything, they each do a
single `ScheduledJob.findOne({_id, shopDomain, status:'pending'})`
lookup.

--- How values are saved to state ---
Each `<select>`'s onChange handler updates `config` via the same
pattern, in-place, immediately on selection (not deferred to Save):
  onChange={(e) => setConfig((c) => ({ ...c, cartAbandonDelay: Number(e.target.value) }))}
(and the equivalent for checkoutAbandonDelay/browseAbandonDelay) --
`e.target.value` (a string, since HTML <select> option values are
always strings) is coerced to a Number before being written into
`config` state, so `config.cartAbandonDelay` etc. always holds a
genuine number matching one of the option `value`s (30/60/120/360/0 or
15/30/60/0), never a string. This ONLY updates local React state --
nothing is sent to the backend until the merchant clicks "Save
automation settings" (SECTION 6, saveConfig(), lines 161-187), which
PATCHes the whole config object (including cartAbandonDelay/
checkoutAbandonDelay/browseAbandonDelay, plus the untouched
lapsingDelay/winbackDelay carried through as-is) to PATCH
/api/automation/:shop in one request.
