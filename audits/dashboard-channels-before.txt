2. DATA MODELS
======================================================

A. ScheduledJob (backend/models/ScheduledJob.js)
   All automation sends go through this model.

   Key fields:
     _id, shopDomain, profileId (ObjectId, links to Profile)
     channel:       'push' | 'email' | 'whatsapp'
     status:        'pending' | 'sent' | 'cancelled' | 'failed' | 'skipped'
     signalType:    cart_abandon | browse_abandon | checkout_abandon |
                    high_intent | price_hesitation | post_purchase_d3 |
                    lapsing | email_capture | cod_to_prepaid | winback | null
     purpose:       'followup' | 'order'  (for whatsapp jobs)
     runAt:         Date — when to send (pending jobs)
     sentAt:        Date — when actually sent (sent jobs)
     payload:       Mixed {
                      push:  title, body, imageUrl, url
                      email (rule-based): subject, body
                      whatsapp: not used (see messageText)
                    }
     messageText:   String — final WhatsApp message text (max 1000)
     outcome:       'delivered' | 'clicked' | 'converted' | 'failed' | 'skipped' | null
     clickedAt:     Date
     createdAt, updatedAt (timestamps: true)
   TTL: 90 days from createdAt

   NOTE: PENDING means status='pending' AND runAt is in the future (or runAt <= now
   but not yet claimed by the poller). "Queued" in the old queue screen = status='pending'.

B. Profile.messages (brain email side-channel)
   Brain-scheduled emails are NOT a separate ScheduledJob.
   They are sent as a side effect of a push ScheduledJob and recorded in
   Profile.messages: { channel:'email', type:signalType, sentAt, outcome:'sent', jobId }
   → today-stats counts these via Profile aggregate.
   → No separate "email pending" for brain emails (they are pending as push jobs).

C. Existing channels endpoints (all reusable):
   GET /api/queue/:shopDomain?status=&page=&limit=
     Returns paginated ScheduledJob list enriched with profile email.
     Fields: _id, channel, status, signalType, payload, sentAt, runAt, profileId, email (enriched).
     CAN be reused for per-item detail view.

   GET /api/whatsapp/:shopDomain/stats?from=&to=
     → { pending, sent, sentFollowup, sentOrder, clicked, carted, purchased, canMessageCount }
     CAN be called from the new channels summary endpoint.

   GET /api/whatsapp/:shopDomain/pending?limit=
     → { total, items: [{ profileId, name, email, phone, consentedAt }] }
     CAN be reused for WhatsApp pending items in detail view.

3. WHAT "SENT" AND "PENDING" MEAN PER CHANNEL
======================================================

PUSH:
  SENT    = ScheduledJob: channel='push', status='sent', sentAt in [from,to]
  PENDING = ScheduledJob: channel='push', status='pending'
            (includes jobs scheduled for the future and jobs runAt<=now awaiting poll)
  Types   = group by signalType

EMAIL:
  SENT    = TWO sources:
            (a) ScheduledJob: channel='email', status='sent', sentAt in [from,to]
                (legacy rule-based email jobs)
            (b) Profile.messages: channel='email', sentAt in [from,to]
                (brain-scheduled emails, sent alongside push)
            → Use Profile aggregate (same as today-stats) for the summary count;
              it captures both paths because brain-email writes to Profile.messages
              AND rule-based email also writes there (Profile.messages is the
              authoritative sent log for email, per today-stats implementation).
  PENDING = ScheduledJob: channel='email', status='pending'
            (only rule-based email jobs; brain emails have no separate email ScheduledJob)
  Types   = group by signalType

  NOTE: Profile.messages does NOT store signalType-level grouping for the type
  breakdown. For email sent types, query ScheduledJob channel='email',status='sent'
  for type breakdown; fallback label "Automation" for brain emails.

WHATSAPP:
  SENT    = ScheduledJob: channel='whatsapp', status='sent', sentAt in [from,to]
            Breakdown: purpose='followup' vs purpose='order'
  PENDING = Count of opted-in profiles (channels.whatsapp.consentedAt exists,
            channels.whatsapp.optedOutAt is null) that have NEVER received ANY
            whatsapp job (distinct profileId not in any ScheduledJob for this shop
            with channel='whatsapp'). This is the EXISTING /stats logic.
  Types   = 'followup' (sent follow-up message) vs 'order' (order confirmation)

EXACT STATUS VALUES COUNTED AS SENT:  status = 'sent'
EXACT STATUS VALUES COUNTED AS PENDING: status = 'pending'
STATUSES NOT COUNTED: 'cancelled', 'failed', 'skipped'
