STEP 1 — BACKEND
======================================================

New file: backend/routes/dashboard.js
Registered: backend/server.js, line ~167

Endpoint 1: GET /api/dashboard/:shopDomain/channels?from=&to=
  Auth: requireAuth + requireStoreOwner (shopDomain-scoped)
  Returns: { push:{sent,pending,types[]}, email:{...same}, whatsapp:{sent,pending,sentFollowup,sentOrder} }
  Push/email: 4 ScheduledJob.aggregate() calls in Promise.all (no N+1)
  Email sent total: Profile.aggregate over messages (same as today-stats — both paths)
  WhatsApp: ScheduledJob.find + Profile.find + ScheduledJob.distinct (only if opted-in exist)
  type[] shape: { type, label, sent, pending, preview } — latest payload as representative

Endpoint 2: GET /api/dashboard/:shopDomain/channels/:channel/items?status=sent|pending&type=&page=&limit=
  Auth: same
  Limit capped at 50. Page defaults to 0.
  WhatsApp pending: from Profile records (opted-in minus contacted), not ScheduledJob
  All other cases: ScheduledJob.find + countDocuments + Profile.find enrichment
  Profile enrichment: channels.email.address only — no push tokens, phones, or other PII
  nameFromEmail: derives display name from local-part only (no raw email in name field)

  Covers: zero counts, push type merging, email Profile.messages aggregate, WA purpose breakdown,

======================================================
RISKS / KNOWN LIMITATIONS
======================================================

1. Email sent count (summary card) uses Profile.messages aggregate, which counts
   both brain+rule paths. The items list uses ScheduledJob only, which means
   brain-email jobs appear as push items (not email) in the items view. The
   email items drawer will show fewer items than the sent count on the card
   for shops that use the brain email path heavily. This matches the audit's
   "known risk" note and requires a separate Profile.messages→items join to fix.

2. WhatsApp pending is still an all-time count (not filtered by date range).
   This is the same behaviour as the existing /stats endpoint and is preserved
   intentionally per spec ("pending = right now").

3. WA pending item name: derived from email local-part if no profile.name.
   Some items may show "Anonymous" if the profile has neither email nor name.
   This matches the existing pending list behaviour.

4. Mobile breakpoint for the drawer: uses the same isMobileView state (≤768px)
   as the rest of Today.jsx. The drawer goes full-screen on mobile.

5. No skeleton/placeholder for drawer loading state — shows "Loading…" text only.
   A future iteration could add skeleton rows for better perceived performance.
