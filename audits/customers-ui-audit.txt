4. STAGE COLUMN — what values can it have
====================================================================

The rendered label (stageLabel / getStageLabel(p)) can be exactly one
of these 5 strings, evaluated in this priority order (first match
wins — see section 1's 4-branch logic):

  1. "Repeat buyer"   — p.orders?.count >= 2
  2. "Bought once"    — p.orders?.count === 1
  3. "Has a cart"     — p.identifiers?.cartTokens?.length > 0 AND
                         p.orders?.count === 0
  4. one of STAGE_CONFIG's 4 label values, keyed by the raw p.stage
     field (lines 121-126):
       p.stage === 'customer'   -> "Bought once"
       p.stage === 'identified' -> "Has a cart"
       p.stage === 'anonymous'  -> "Visitor"
       p.stage === 'lapsed'     -> "Going quiet"
  5. FALLBACK: the raw p.stage string itself, unmodified, if it is
     truthy but not one of the 4 known keys above (STAGE_CONFIG[p.stage]
     is undefined, so `STAGE_CONFIG[p.stage]?.label || p.stage`
     evaluates to p.stage) — bg defaults to '#f3f4f6', color to
     '#6b7280' in that case.

So the FULL set of strings the UI can actually show is: "Repeat
buyer", "Bought once", "Has a cart", "Visitor", "Going quiet", or
(rarely, only for a p.stage value outside the 4 known ones) whatever
raw string is stored in the profile's own .stage field in Mongo.

Note branches 1-3 are computed FROM orders/cartTokens data and take
priority OVER whatever p.stage itself says — e.g. a profile whose
stored p.stage is still 'identified' but which has since placed 2
orders would show "Repeat buyer" (branch 1), not "Has a cart".
