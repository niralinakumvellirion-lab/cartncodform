2. Step completion logic
================================================================================
  - 'embed'      : manual only. Checkbox is interactive ONLY for this id
                   (disabled for the other three). toggleManual('embed', checked)
                   sets steps[embed].done.
  - 'automation' : auto — `automationRules.some(r => r && r.active)` (>= 1 active
                   rule). Sticky-once-true.
  - 'push'       : auto — `customers.some(c => c && c.status && c.status !== 'abandoned')`
                   (>= 1 non-abandoned row = a recovery happened). Sticky-once-true.
  - 'cod'        : `codCopied` local state — true once the link is copied.

Recompute mechanism: `automationDone` and `pushDone` are computed as PRIMITIVE
booleans on each render, and a useEffect keyed on
[automationDone, pushDone, codCopied] patches steps[].done. Using primitives
(not the arrays) as deps means the effect only fires when a signal actually
flips — the inline `automationRules={[]}` prop (new ref every parent render)
does NOT cause a render loop.
"Checked on mount + on each tab change": the effect runs on mount; a tab
change re-renders StoreView -> fresh props flow down -> effect re-evaluates
(no-op unless a signal changed, which is the intended behaviour since the
underlying data only changes on load()).

5. showOnboarding state — initialized correctly
================================================================================
CONFIRMED. In StoreView:
  const [showOnboarding, setShowOnboarding] =
    useState(() => !isOnboardingDismissed());

isOnboardingDismissed() (module-level helper):
  try {
    return typeof window !== 'undefined'
      && window.localStorage.getItem('ccf_onboarding_dismissed') === 'true';
  } catch { return false; }

=> showOnboarding starts TRUE unless the key is exactly 'true'; a throwing /
unavailable localStorage is treated as "not dismissed" (checklist shows).
Lazy initializer so localStorage is read once, on the client, at mount.
Belt-and-suspenders: the component ALSO holds its own `dismissed` state seeded
the same way and returns null when dismissed, so both the parent gate and the
component agree.

Dismissal writes 'ccf_onboarding_dismissed' = 'true' in BOTH places (the
component's own dismiss() and StoreView's onDismiss handler) — redundant but
harmless, and matches the task's "sets localStorage + calls onDismiss()".

9. DEVIATIONS FROM THE LITERAL SPEC (all deliberate)
================================================================================
(a) showOnboarding / dismissed init: the spec's inline expression
    `typeof window !== 'undefined' && localStorage.getItem(...) !== 'true'`
    would throw (uncaught) where localStorage access is blocked. Extracted to
    isOnboardingDismissed() with try/catch; same result when storage works.

(b) onTabChange handler: the spec used `setSelectedTab(idx)`, but StoreView has
    no such setter — its tab state is `tab` (a string id) via `setTab`, and
    `selectedTab` is derived (`tabs.findIndex(...)`). Implemented as
    `if (['abandoned','cod','automation'].includes(tabId)) setTab(tabId)`,
    which is the correct bridge for the real state model. Tab ids line up
    exactly with what OnboardingChecklist requests ('automation','abandoned').

(c) 'automation' step: automationRules is passed `[]` (StoreView doesn't fetch
    rules), so this step never auto-completes. Its Checkbox is `disabled`
    (auto step), so a merchant currently CANNOT tick it manually either — it
    just stays open. Per the spec's own note this step is "empty for now";
    wiring StoreView to the rules API (or enabling this one checkbox) is a
    follow-up. Progress can still reach "3 of 4".

(d) Action Button: added `external={Boolean(step.actionUrl)}` (not in the
    spec's Button snippet). The only real actionUrl is the Shopify Theme
    Editor; inside the embedded app iframe a same-frame navigation to
    admin.shopify.com is blocked by frame-ancestors, so it must open in a new
    tab.

(e) Checkbox: `disabled={step.id !== 'embed'}` and toggleManual() early-returns
    for non-'embed' ids — enforces the spec's "user marks manually" applying
    to the embed step only (the other three are derived). Checkbox `label` is
    the step title with `labelHidden` (Polaris requires a non-empty label for
    a11y; the visible bold title sits beside it).

(f) 'cod' step description is built as
    `Share your COD order form link with customers: ${codLink}` where
    codLink = `https://${shop}/apps/cartncodform/cod-form` — i.e. the live
    shop domain is interpolated rather than left as a literal "{shop}".
