2. Where OAuthState is read/verified during /callback
====================================================================

Exact read + delete code, GET /api/auth/callback handler (lines
70-159), the relevant lines:

  72    const { shop, code, state } = req.query;
  73
  74    if (!shop || !code || !state) {
  75      return res.status(400).json({ error: 'Missing shop, code or state in callback' });
  76    }
  77
  78    // Validate + consume the state nonce (single use).
  79    const savedState = await OAuthState.findOneAndDelete({ nonce: state });
  80    if (!savedState) {
  81      return res.status(400).json({ error: 'Invalid or expired OAuth state' });
  82    }

The incoming `state` query param (Shopify echoes back whatever value
was sent on the original authorize redirect) is looked up AND deleted
in a single atomic operation, `OAuthState.findOneAndDelete({ nonce:
state })` — this is a combined read+consume: if a document with that
exact nonce exists, it is returned AND removed from the collection in
one step (so the same nonce cannot be replayed a second time). If no
matching document is found (`savedState` is null/falsy — either the
nonce never existed, was already consumed by a prior callback, or its
TTL index expired it), the callback rejects with 400 "Invalid or
expired OAuth state" and does not proceed to exchange the code or
touch Store at all. If found, `savedState.ownerEmail` (whatever was
optionally passed at /install time) is read a few lines later (line
94 area, not shown here — outside the scope of this audit's 3
questions) to prefer-fill the Store's ownerEmail field.

The HMAC check (`verifyHmac(req.query)`, line 85) is a SEPARATE
verification that runs AFTER the state check succeeds — it only logs
a warning and continues on failure ("continuing in dev mode"), unlike
the state check which hard-rejects with a 400. These are two distinct
security checks: HMAC verifies the request was genuinely signed by
Shopify (using SHOPIFY_API_SECRET); the state nonce verifies this
specific callback corresponds to an install THIS SERVER initiated
and that it has not been used before.

  23    },
  24  }, {});

  26  module.exports = mongoose.model('OAuthState', oAuthStateSchema);

Fields: nonce (String, required, UNIQUE — a second layer of
single-use enforcement beyond the findOneAndDelete pattern: even a
concurrent duplicate nonce could never be inserted twice), ownerEmail
(String, optional, lowercased/trimmed), createdAt (Date, defaults to
Date.now, with a TTL index of 3600 seconds — Mongo auto-deletes the
document exactly 1 hour after creation, which is what "expired"
means in the callback's "Invalid or expired OAuth state" error
message: either genuinely not found because it was never created
with that nonce/was already consumed, or found-but-since-deleted by
this TTL index after sitting unused for over an hour).
