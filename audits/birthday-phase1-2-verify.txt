3b. Poller suppression and consent re-check for birthday jobs
  DEFECTS FOUND AND FIXED:

  DEFECT 1 (critical) — birthday push with null cartToken broadcasts to all subscribers.
    sendPushToCustomers(... null) at server.js:482 (old) queries CustomerPushSubscription
    for the entire shop (no cartToken filter) when cartToken is null, reaching every
    subscriber, not just the birthday profile.
    The sweep creates ScheduledJobs with no cartToken set.

  DEFECT 2 — no profile suppression check before birthday push send.
    Profile could have been suppressed (opted-out) between sweep scheduling and send time.

  DEFECT 3 — no profile suppression check before birthday email send.
    Birthday email branch read the profile with .select('channels identifiers') but never
    checked profile.suppressed.

  FIXES (backend/server.js):
    Push: added block before sendPushToCustomers (after copy resolution):
      - Profile.findById(job.profileId).select('suppressed channels identifiers')
      - if suppressed → skip with 'profile_suppressed'
      - if !channels.push.subscribed → skip with 'push_consent_withdrawn'
      - if no cartTokens[0] → skip with 'no_push_token'
      - job.cartToken = cartTokens[0]  (so sendPushToCustomers targets only this profile)
      - Only applies when signalType==='birthday' && profileId && !job.cartToken
        (retry jobs that already have cartToken skip this block)

    Email: changed .select('channels identifiers') to .select('suppressed channels identifiers')
      and added: if (bdProfile && bdProfile.suppressed) → skip with 'profile_suppressed'
      before the email address lookup.

  TESTS ADDED: backend/__tests__/birthday-phase2-poller.test.js (7 new tests)

    - Push: push.subscribed=false → skipped (push_consent_withdrawn)
    - Push: cartTokens=[] → skipped (no_push_token)
    - Push: valid profile → sendPushToCustomers called with profile's cartToken
    - Push: job already has cartToken (retry) → sendPushToCustomers called, profile block bypassed
    - Email: suppressed → skipped, sendMarketingEmail not called

  The 9am run time (_bdayRunAt) calls zonedTimeToUtc(cur.y, cur.mo, cur.d, 9, 0, resolved)

  REPORT ONLY — no change.

3d. Frequency cap bypass
  File: backend/server.js:197-210 (isOverFrequencyCap), 375

  Birthday jobs have no cartToken and no customerId (sweep doesn't set them).
  isOverFrequencyCap builds orClauses from cartToken and customerId; when both are null
  the clause array is empty → the function returns false → birthday sends always bypass
  the 3/24h frequency cap.

  INTENTIONAL: the per-year lastOfferYear guard in the sweep is the actual rate limit
  (one send per year per profile, regardless of how often the sweep runs).

  Other messages the same profile could receive the same day: brain.js-scheduled jobs
  (cart_abandon, browse_abandon, etc.) still go through frequency cap via their own
  cartToken/customerId. The birthday job does NOT count toward the cap AND does not
  protect the profile from receiving a non-birthday message the same day. A profile
  could receive a birthday email and a separate cart-abandon push on the same day.

  REPORT ONLY — behaviour unchanged per instruction.
