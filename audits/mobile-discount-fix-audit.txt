BUG 3 FIX: popup re-appears after successful discount
─────────────────────────────────────────────────────────────────────────────
Part A — renderDiscountCode() (line ~765):
  Added sessionStorage.setItem('ccf_disc_redirected', '1') as the FIRST write
  inside the existing try block (before ccf_active_discount + ccf_active_pct).
  This mirrors what injectProductNudge() already does.
  After the redirect, canPromptForDiscount() sees ccf_disc_redirected = '1'
  and returns false, blocking the saveToken() re-prompt.

Part B — showSoftPrompt() guard (line ~847):
  Added: if (isDiscountCapture && promptAlreadyShown()) return;
  Context: when permission === 'granted' and discount enabled, isDiscountCapture
  = true, which bypasses canPrompt() (and its promptAlreadyShown check) entirely.
  Without this extra guard, any intent trigger (dwell, scroll, add_to_cart) fired
  after cleanup() would re-open the popup in the same session — cleanup() removes
  the DOM element (getElementById check passes) but sessionStorage.ccf_prompt_shown
  remains 'true'. The new guard short-circuits before the element check.

Guard for SUBSCRIBED_KEY:
  canPrompt() at line 90–93 already returns false when
  localStorage.SUBSCRIBED_KEY === '1', blocking the non-discount-capture path.
  The discount-capture path is now additionally guarded by promptAlreadyShown()
  (Part B), which covers the same-session re-trigger. Cross-session re-trigger
  (new tab, fresh sessionStorage) is intentional behaviour — the discount popup
  re-shows for unrecognised sessions so the customer can still claim.
