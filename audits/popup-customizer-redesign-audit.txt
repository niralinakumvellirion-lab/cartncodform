3. GALLERY -> EDITOR -> BACK NAVIGATION
====================================================================
New state: popupEditorOpen (bool, default false), reset to false every
time showPopupCustomizer is toggled (both when opening the trigger card
and when closing the whole customizer via "←") — re-opening always lands
on the gallery, per the task's Step 1 description.
  Trigger card "Customize popup" -> showPopupCustomizer=true,
    popupEditorOpen=false -> gallery renders.
  Gallery card click -> setActiveStyle({styleId, ...layout}) +
    popupEditorOpen=true -> editor renders for that style/layout.
  Editor "← Back to styles" -> popupEditorOpen=false -> gallery renders
    again (customizer stays open).
  Editor/gallery outer "←" -> showPopupCustomizer=false,
    popupEditorOpen=false -> collapsed trigger card.
Gallery selection state: a card is marked "✓ Selected" when
activeStyleId matches AND (for Classic) the card's layout matches
activePopup.layout — correctly device-aware since activeStyleId/
activePopup already resolve per the existing mobileStyleOverride logic
from the earlier popup-style task.
Classic-Split is disabled (dimmed, unclickable) on the Mobile device
tab, since mobilePopup.layout's schema enum only allows 'card'|'banner'
— matching the pre-existing restriction that the OLD Layout picker was
already desktop-only for exactly this reason.

4. INLINE EDIT BEHAVIOUR — TextEditRow
====================================================================
- Pencil button (✏️, aria-label="Edit <label>") AND clicking the value
  itself both open edit mode — both are real <button type="button">
  elements.
- Opening edit mode sets the shared editingField state to this row's
  fieldKey; ANY other row's edit mode (if open) closes automatically,
  since each row's own `editing` check is `editingField === fieldKey` —
  only one can ever be true at a time, confirmed structurally (single
  piece of state, not per-row local state).
- Enter: preventDefault() then commits (writes via onCommit, then
  clears editingField). Native Enter-triggered form submission isn't a
  risk here — there is no surrounding <form> element.
- Blur: commits the same way. Enter doesn't itself cause a duplicate
  blur-commit, since these inputs aren't inside a <form> and Enter
  doesn't programmatically blur a plain <input>.
- Escape: preventDefault() then ONLY clears editingField — onCommit is
  never called, so the underlying popup/mobilePopup state was never
  touched during that edit session; the row reverts to showing whatever
  value it already had.
- Empty value: shows the row's placeholder text in muted grey, or a
  plain "—" for the two rows with no natural placeholder concept
  (Brand name has one; every text row falls back to '—' only if BOTH
  value and placeholder are empty).

5. PREVIEW PARITY WITH ccf-push.js — PRESERVED, PLUS TWO REAL FIXES
   FOUND ALONG THE WAY
====================================================================
The interactive preview embedded at the top of the editor (StepBar,
Replay, the Desktop/Mobile-aware ClassicPreview/StyleCardPreview
rendering, the real-values button/close/countdown parity from the two
prior tasks) is the EXACT SAME popupPreviewCard content, just relocated
— its own former "Desktop preview"/"Mobile preview" heading was removed
(redundant now that the device toggle sits directly above it in the
editor), but the StepBar/Replay/preview-dispatch JSX itself is
byte-identical to before this task. No preview-vs-storefront value was
touched in this task.

Two REAL, PRE-EXISTING UI bugs were found (not introduced by this task)
while building the new compact rows and deciding which rows to show per
style, both now fixed as a side effect of the redesign:
  1. "Text position" (textAlign) and "Brand name" rows were shown,
     full-width, for EVERY style before this task — including Flash
     Sale and Gift Reveal, whose ccf-push.js builders never read either
     field (confirmed: brandName/textAlign do not appear anywhere in
     the flash_sale/gift_reveal branch of showSoftPrompt(), nor in
     StyleCardPreview). Editing either field for those two styles did
     nothing visible, with no indication why. Now gated to
     `activeStyleId === 'classic'` only, matching what actually renders.
  2. "Dark overlay" (showOverlay) had the same problem — ccf-push.js's
     overlay logic only exists inside the split-layout branch (the
     comment there literally says "Dark overlay behind the popup (split
     layout only, unless disabled)"); card/banner/flash_sale/
     gift_reveal never create one, so this toggle was previously shown
     (and editable) for every style with zero effect outside Classic
     Split. Now gated to `activeStyleId === 'classic'` — technically
     still one field wider than reality (Classic Card/Banner also don't
     use it), but narrowing it exactly to "only shown for Split" would
     have meant hiding it based on a SECOND condition (layout, not just
     style) that the task's own grouping ("Appearance" section, one
     flat list) doesn't obviously call for; flagged here as a
     residual, honest gap rather than silently claiming full precision.
These are UI-visibility fixes only — the underlying fields
(brandName/textAlign/showOverlay) are untouched in the schema/save
payload, and still save/load exactly as before for shops that already
set them under a non-classic style (the stored value simply isn't
shown/editable from a style where it doesn't apply, matching the
task's spirit of the "current settings" gallery preview always being
accurate).

6. KEYBOARD ACCESS + <900px LAYOUT
====================================================================
- Every interactive control is a real <button>, <input>, or <select> —
  no click-only <div>s were introduced (the OLD Dark overlay toggle and
  a few OLD pill rows used bare onClick <div>s in places; every
  equivalent NEW row component — ToggleRow, PillsRow, TextEditRow,
  ImagePositionGrid, GalleryCard — uses <button type="button"> with
  aria-pressed/aria-label/aria-disabled as appropriate).
- Visible focus: every new interactive element carries className=
  "ccf-style-focus" (or "ccf-style-card" for gallery cards), both
  already wired to the page's existing :focus-visible outline rule (no
  new CSS needed).
- Enter/Escape behaviour: see section 4.
- <900px layout: the editor is UNCONDITIONALLY a single vertical column
  — preview area, then compact settings — at every viewport width, not
  just below 900px. This trivially satisfies "under ~900px the preview
  stacks above the settings" (it's true at every width, so it's true
  there too) rather than requiring a dedicated breakpoint switch; no
  side-by-side arrangement was implemented for wide viewports, since
  the task's Step 2 description itself frames the editor as "TOP:
  preview... BELOW: settings" unconditionally, with the <900px note
  read as the one explicit responsive requirement rather than an
  implication that wide viewports need a DIFFERENT (side-by-side)
  arrangement. The outer page grid around the customizer was also
  changed: when showPopupCustomizer is true, popupCard now renders
  full-width (max-width 960px, centered) instead of being squeezed into
  the old 380px sticky right column occupied by a separate preview
  card — necessary since the preview is no longer a separate card once
  it's embedded in the editor.
- Gallery grid itself reuses the existing isMobileView (768px) state
  for its own column count (2 columns narrow / auto-fill wide) — a
  separate, smaller decision from the 900px preview-stacking
  requirement above, which needed no dedicated breakpoint.
