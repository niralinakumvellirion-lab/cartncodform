*** ONE DEVIATION FROM THE SPEC — FLAGGED, READ FIRST ***
Spec step 4 for requireAuth says:
  "payload.iss must start with 'https://' and end with '.myshopify.com'"
A REAL Shopify session token's `iss` is
  "https://<shop>.myshopify.com/admin"
— it ends with "/admin", NOT ".myshopify.com". Only `dest`
("https://<shop>.myshopify.com") ends with ".myshopify.com".
Implemented literally, the iss check would 401 EVERY real token.

WHAT WAS IMPLEMENTED (a strict superset of the spec):
  iss is a string, starts with "https://", AND
  iss.replace(/\/admin\/?$/, '').endsWith('.myshopify.com')
i.e. an optional trailing "/admin" is stripped before the host
check. This accepts everything the literal spec would accept
PLUS real Shopify tokens. `dest` is checked exactly as specified
(literal ".endsWith('.myshopify.com')" — correct, dest has no
path). If the intent really was the literal iss string, revert
that one line.

NEW requireAuth LOGIC (backend/middleware/requireOwner.js)
================================================================
  1. Authorization header -> Bearer token (unchanged).
     - missing  -> 401 { error: 'Missing Authorization header' }
  2. secret = process.env.SHOPIFY_API_SECRET
     - unset    -> 500 { error: 'Server auth misconfigured' }
       (logs '[auth] SHOPIFY_API_SECRET not configured on backend')
  3. jwt.decode(token, { complete: true })   (NO verification)
     - null / no header / no payload -> 401 { error: 'Malformed session token' }
  4. jwt.verify(token, SHOPIFY_API_SECRET, {
       algorithms: ['HS256'],
       ignoreExpiration: true,   // exp/nbf checked manually in step 5
       ignoreNotBefore: true,
     })
     - any throw -> 401 { error: 'Invalid session token' }
       (logs '[auth] Session token verification failed: <msg>')
  5. CLAIM VALIDATION (each -> 401 with a descriptive error):
       iss   : typeof string, startsWith 'https://',
               and (iss without a trailing '/admin') endsWith '.myshopify.com'
               -> 401 { error: 'Session token: invalid iss claim' }
       dest  : typeof string, startsWith 'https://', endsWith '.myshopify.com'
               -> 401 { error: 'Session token: invalid dest claim' }
       aud   : === process.env.SHOPIFY_API_KEY
               -> 401 { error: 'Session token: aud does not match this app' }
       exp   : typeof number and exp  >  Date.now()/1000
               -> 401 { error: 'Session token expired' }
       nbf   : typeof number and nbf  <=  Date.now()/1000 + 10   (10s skew)
               -> 401 { error: 'Session token not yet valid' }
  6. shopDomain = new URL(payload.dest).hostname
       - URL() throw -> 401 { error: 'Session token: unparseable dest claim' }
  7. SETS ON req:  req.shopDomain = shopDomain    (e.g. 'cartncod-form.myshopify.com')
     (req.userEmail is GONE — no longer set anywhere.)
  8. next()

  Doc comment updated to describe the session-token flow.
  Imports unchanged: jsonwebtoken, ../models/Store (both still used).
