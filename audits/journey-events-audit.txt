2. What event types are currently shown
====================================================================
Two different, DIFFERENT answers depending on what "shown" means here
-- worth separating clearly:

a) What event types the BACKEND query can return (i.e. what could
   ever appear in recentEvents): ALL of them, unfiltered. The
   StorefrontEvent.find() call (section 3 below) has no `type`
   condition at all -- it matches purely on shopDomain + sessionId/
   cartToken membership, so any event type ever recorded for that
   profile's identifiers can appear, sorted newest-first, capped to
   the 20 most recent. Grepping this codebase's storefront tracker
   (extensions/cartncodform-embed/blocks/push-notifications.liquid)
   for every `trackEvent('<type>', ...)` call site shows the following
   are the types that actually ever get recorded in practice: page_view,
   product_view, collection_view, search, cart_view, reached_checkout,
   add_to_cart, page_exit, push_prompt_shown, push_prompt_accepted (and
   whatever a customer's own denial path records -- not traced further
   here since it wasn't part of what this task asked to read). Any of
   these can show up in a given customer's Recent activity list.

b) What event types have a DEDICATED icon/label mapping on the
   frontend: only 6 -- see EVENT_ICONS (section 3 below). Every OTHER
   type (collection_view, search, cart_view, reached_checkout, and any
   future/unlisted type) still renders -- the row itself doesn't
   disappear or error -- but falls back to a generic bullet icon ('•')
   via `EVENT_ICONS[e.type] || '•'` (line 768), with its label
   generated generically from the raw type string (see section 3
   below, "How each event type is displayed").

So: nothing is filtered out or hidden by type anywhere in this
pipeline (backend or frontend) -- every event type that exists for a
customer can appear in the list, and the frontend degrades gracefully
(bullet + auto-generated label) for the 4+ types it doesn't have a
custom icon for, rather than omitting them.
