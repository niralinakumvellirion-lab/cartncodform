5. ISSUES / NOTES
-----------------
  (a) Onboarding "Set up" steps: STEPS 'voice' and 'signals' use
      actionType:'nav' -> onNavigate('settings'), and 'push' -> onNavigate
      ('customers'). In admin/page.js onNavigate is now () => {}, so those
      three step buttons visually do nothing (they still toggle the step's
      done state via handleAction's toggleStep call). The 'embed' step
      (actionType:'url') still opens the theme editor. Not blocking; a
      follow-up could point onNavigate at router.push('/admin/settings-page'
      / '/admin/customers').
  (b) The 6 new route wrappers do NOT run the onboarding check — deep-linking
      to /admin/customers etc. always shows that screen with the nav, even
      for a brand-new install. Onboarding only gates the /admin index. This
      matches the spec (onboarding logic stays only in admin/page.js).
  (c) Each new route re-declares the NavMenu block inline (7x duplication).
      Acceptable per the spec's explicit template; a shared <AdminChrome>
      component would DRY it up later.
  (d) settings-page vs settings: the route is intentionally /admin/settings-page
      (the spec's name) — if a Shopify app URL or theme link points at
      /admin/settings it will 404. Flagged for whoever wires deep links.
  (e) No screen component files were modified; Today.jsx still has its own
      <Page> wrapper added earlier, so the new /admin/signals + /admin/insights
      routes render the full Today screen.
