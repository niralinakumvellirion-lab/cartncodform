1. BACKEND — product-analytics route
------------------------------------
  Added to backend/routes/events.js, immediately before module.exports:
    GET /api/events/:shopDomain/product-analytics
      - requireAuth + requireStoreOwner
      - shopDomain trimmed + lowercased into `shopDomain` const
      - 30-day $match/$group/$project/$sort/$limit-20 pipeline over
        StorefrontEvent, grouping by meta.productId; per product:
        productTitle ($last), productPrice ($last), views (product_view count),
        uniqueViewers ($size of $addToSet sessionId), addToCarts, pageExits,
        totalDwell ($sum of meta.dwellSeconds on product_view rows),
        cartRate ($round(addToCarts/views*100, 1)),
        avgDwell ($round(totalDwell/views, 0))
      - store-level (7-day) via Promise.all of 4 countDocuments +
        1 distinct('sessionId'):
          productViewsThisWeek = product_view count
          sessionCount         = distinct sessionId length
          addToCartRate        = (add_to_cart / sessionCount * 100).toFixed(1)
          allowedNotifications = (push_prompt_accepted /
                                  push_prompt_shown * 100).toFixed(1)
      - res.json({ stats: { productViewsThisWeek, allowedNotifications,
        addToCartRate, sessionCount }, products })
      - try/catch -> 500 { error }
    Pipeline implemented VERBATIM from the spec (the two loose bits — an
    undeclared `shopDomain` in the store-stats block and `req.params.shopDomain`
    used raw in $match — were normalised to the trimmed/lowercased `shopDomain`
    const for consistency with the rest of the file).
  node --check backend/routes/events.js -> OK

  FIELD-NAME NOTE (observation, not a change): the pipeline reads
  meta.productTitle / meta.productPrice / meta.dwellSeconds. The current
  storefront block (extensions/.../push-notifications.liquid) emits
  product_view meta as { productId, title, price, vendor, type, variantId,
  imageUrl } and puts dwellSeconds on page_exit, not product_view. So with
  today's data productTitle/productPrice come back null and avgDwell is 0
  until either the pipeline field names or the storefront meta keys are
  aligned. views / uniqueViewers / addToCarts / cartRate work as-is
  (productId + type are present). Left exactly as the spec dictates.
