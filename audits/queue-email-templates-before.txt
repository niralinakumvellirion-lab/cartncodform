=== QueueScreen.jsx — openAddEngStep email branch (broken) ===

Fetch (QueueScreen.jsx line 1581-1585):
  if (emailTemplates.length === 0) {
    apiGet(`/api/email-templates/${encodeURIComponent(shop)}`)
      .then(d => setEmailTemplates(d.templates || []))
      .catch(() => {});
  }

WHY IT ALWAYS RETURNS EMPTY:
  The URL `/api/email-templates/${shop}` (e.g. /api/email-templates/mystore.myshopify.com)
  is treated by Express as /api/email-templates/:id with id = "mystore.myshopify.com".
  This hits `router.get('/:id')` (emailTemplates.js:374) which looks up an EmailTemplate
  by MongoDB _id — a shopDomain is not a valid _id → 404.
  The `.catch(() => {})` swallows the error.
  emailTemplates stays [].

Secondary issues (would matter even after fixing the URL):
  1. `if (emailTemplates.length === 0)` guard: if a successful empty list is ever
     returned, the component never refetches on subsequent opens.
  2. No loading state: "No saved email templates" shown immediately while fetching.
  3. No error state / retry: a network failure is silently swallowed.

Template rendering (lines 1090-1103):
  - 2-column grid (not a list like CustomerDetail)
  - No radio dot, no type chip, no subject preview
  - t.name || t.subject || 'Untitled' — no dedicated name field
  - className `ccf-tpl-card selected` — relies on injected CSS class (may or may not exist)
  - "✓ Selected" text, no preview iframe

No template preview: selecting a template does NOT call /api/email-templates/:id/preview,
shows no iframe, no Desktop/Mobile toggle.

Save button: `disabled={... || emailTemplates.length === 0}` — always disabled because
the array is always empty due to the URL bug.
