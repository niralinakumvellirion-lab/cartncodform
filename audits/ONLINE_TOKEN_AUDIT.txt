ONLINE TOKEN (OAuth Token Exchange) — SELF AUDIT
=================================================
Date: 2026-09-11
Files: backend/models/Store.js, backend/utils/shopify.js,
       backend/routes/auth.js, backend/routes/discounts.js


STEP 1 — backend/models/Store.js
---------------------------------
Added, next to `needsReauth`:
  onlineAccessToken:     { type: String, default: null },
  onlineTokenExpiresAt:  { type: Date,   default: null },
Documented as a short-lived (shpua_) token minted via Token Exchange from a
live App Bridge session, preferred over the offline `accessToken` when
present and unexpired.


STEP 2 — backend/utils/shopify.js
----------------------------------
Added and exported  getOnlineToken(shop, sessionToken):
  - POSTs to https://{shop}/admin/oauth/access_token with
    grant_type = urn:ietf:params:oauth:grant-type:token-exchange,
    subject_token = sessionToken,
    subject_token_type = urn:ietf:params:oauth:token-type:id_token,
    requested_token_type = urn:shopify:params:oauth:token-type:online-access-token
  - Returns { token: data.access_token, expiresAt: data.expires_in ? new
    Date(Date.now() + data.expires_in * 1000) : null }.
The earlier exchangeSessionToken() (offline-token variant, added last task)
was left in place and still exported — not removed, just no longer called
from the refresh-token route.


STEP 3 — backend/routes/auth.js
---------------------------------
POST /api/auth/refresh-token now calls getOnlineToken instead of
exchangeSessionToken:
  - sessionToken read from req.headers.authorization?.split(' ')[1]
  - on missing token: 400 { success: false }
  - on !token from getOnlineToken: 502 { success: false }
  - on success: Store.updateOne({ shopDomain: req.shopDomain },
      { $set: { onlineAccessToken, onlineTokenExpiresAt, needsReauth: false } })
  - on thrown error (axios/OAuth failure): 502 { success: false, error:
    err.message } — err.response.data (Shopify's OAuth error JSON) is logged
    server-side only via err.message-style logging, never the token itself.
Import list updated: exchangeSessionToken -> getOnlineToken (auth.js no
longer references exchangeSessionToken; it remains available from
utils/shopify.js for any other caller).


STEP 4 — backend/routes/discounts.js — generateDiscount()
-----------------------------------------------------------
  - Store.findOne(...).select(...) widened from 'accessToken' to
    'accessToken onlineAccessToken onlineTokenExpiresAt' — REQUIRED for the
    preference logic below to ever see a non-undefined onlineAccessToken.
  - Token selection after the store is loaded:
      let apiToken = store.onlineAccessToken || store.accessToken;
      if (store.onlineAccessToken && store.onlineTokenExpiresAt) {
        if (new Date() > store.onlineTokenExpiresAt) {
          console.log('[discounts] online token expired for', shop);
          apiToken = store.accessToken;
        }
      }
      console.log('[discounts] using token type:',
        apiToken && apiToken.startsWith('shpua_') ? 'online' : 'offline');
  - The GraphQL mutation's 'X-Shopify-Access-Token' header now sends
    apiToken (was store.accessToken). This is the only place the header is
    set in generateDiscount(), confirmed via grep.
  - The store-connectivity guard (`!store || !store.accessToken`) is
    unchanged — the offline token still gates whether the store is
    "connected" at all.

ARCHITECTURAL NOTE (not a code change — flagging for awareness)
-----------------------------------------------------------------
generateDiscount()'s real-world caller is the storefront popup, via the
App-Proxy-signed POST /generate-discount / POST /:shopDomain/generate — a
customer-initiated request with no admin user session. The online token
this step prefers is minted only when an admin has the embedded app open
(Discounts.jsx calls /api/auth/refresh-token on mount) and expires per
Shopify's expires_in (commonly ~24h). So in practice:
  - Right after an admin opens the Discounts screen, storefront-triggered
    discount creation will use the online token for up to ~24h.
  - Once it expires, generateDiscount() silently falls back to the offline
    `accessToken` — the same token this whole thread has been trying to
    get write_discounts onto. If that offline token still lacks the scope,
    ACCESS_DENIED returns and needsReauth is set exactly as before; the
    online-token path does not by itself resolve the root cause.
  - Getting write_discounts onto the offline token still requires either a
    completed re-auth (GET /api/auth/install?shop=...) or a successful
    OFFLINE token-exchange (exchangeSessionToken, still present in
    utils/shopify.js but currently unused) landing the new scope on
    Store.accessToken itself.
No action taken on this note — implementation matches the request exactly;
recorded here per the audit instructions.
