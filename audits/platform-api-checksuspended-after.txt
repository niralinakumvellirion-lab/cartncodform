1. THE 4 LINES, THE COMMIT, AND THE EXACT IMPACT TODAY
═══════════════════════════════════════════════════════════

The 4 uses of checkSuspended in api.js (before fix):
  Line  73: checkSuspended(retryRes.status, err);     [inside apiGet, 401-retry path]
  Line  86: checkSuspended(res.status, bodyJson);     [inside apiGet, first-attempt path]
  Line 147: checkSuspended(retryRes.status, err);     [inside apiSend, 401-retry path]
  Line 155: checkSuspended(res.status, data);         [inside apiSend, first-attempt path]

Where checkSuspended is defined:
  frontend/lib/checkSuspended.js — exported as `export function checkSuspended(status, body)`.
  Fires `window.dispatchEvent(new Event('ccf:store-suspended'))` when:
    status === 403 AND body.code === 'STORE_SUSPENDED'.
  Idempotent (once per page load). Also exports _resetForTest().

Commit that introduced the bug: c151380
  "Move checkSuspended to its own module; add real ESM test"
  The commit removed the inline definition from api.js and added:
    export { checkSuspended } from './checkSuspended';
  This is a re-export only. ESM re-exports do NOT create a local binding — the
  identifier checkSuspended is NOT in scope within api.js for its own use.
  The missing line was: import { checkSuspended } from './checkSuspended';

Impact today:
  (a) Normal successful API call (200 OK):
      checkSuspended is called only in error branches (!res.ok or !retryRes.ok).
      A 200 response returns res.json() without reaching any of the 4 lines.
      NO ReferenceError. No observable regression for the happy path.

  (b) 403 "STORE_SUSPENDED" response:
      Code reaches e.g. `checkSuspended(res.status, bodyJson)`. Since
      checkSuspended is not in scope, JavaScript throws:
        ReferenceError: checkSuspended is not defined
      This is caught by the calling component's error handler as a generic
      error — the merchant NEVER sees the paused-store screen; instead they
      see a generic fetch error. The feature introduced in step 8 is silently
      broken. Any 403 (even non-suspended ones) also throws ReferenceError,
      not the intended "GET /path failed (403)" message.
