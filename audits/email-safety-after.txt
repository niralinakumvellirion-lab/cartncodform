1. backend/utils/unsubscribeToken.js (new)
   - createToken(shopDomain, profileId): HMAC-SHA256 over SHOPIFY_API_SECRET
     on "shopDomain|profileId", token = base64url(payload) + '.' + hex-sig.
   - verifyToken(token): splits on first '.', recomputes HMAC, timing-safe
     compare (crypto.timingSafeEqual). Returns { shopDomain, profileId } or
     null on any failure.
   - buildUnsubscribeUrl: ${BACKEND_URL}/api/unsubscribe/${token}
   - buildUnsubscribeHeaders: per-recipient List-Unsubscribe with https URL +
     mailto fallback, List-Unsubscribe-Post one-click.

6. FestivalQueue.sendClaimedAt: Date, default null (new field, schema-level).

7. processFestivalQueue (server.js):
   - Pre-query now excludes items where sendClaimedAt is set within the last
     15 minutes (claimExpiry = now - 15 min).
   - Per-item atomic claim: findOneAndUpdate({ _id, status:'approved',
     $or:[{sendClaimedAt:null},{sendClaimedAt:{$lt:claimExpiry}}] },
     { $set: { sendClaimedAt: now } }). If null → skip (another tick claimed).
   - Success paths: sendClaimedAt left set (item becomes 'sent', not requeried).
   - Retry paths (status stays 'approved'): $unset sendClaimedAt so next tick
     can reclaim.
   - Catch block: $unset sendClaimedAt with .catch(() => {}) so a DB failure on
     the release doesn't mask the original error.

DECISIONS / TRADE-OFFS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

- No expiry on tokens: SHOPIFY_API_SECRET rotation immediately invalidates all
  outstanding tokens (which is acceptable since the token only needs to work
  until the user clicks it — the window is short). If a strict expiry is needed
  later, a timestamp can be encoded in the payload.

- renderEmailDocument called per-recipient in broadcast and /broadcast: adds
  ~N ms per recipient for string generation. At the BROADCAST_CAP of 90
  recipients this is ~90 × <1ms — negligible vs. network calls to Resend.
  One existing test expected a single render for 2 recipients; updated to
  expect 2.

- sendAbandonedCartEmail without profileId (webhooks.js, push.js test-send):
  falls back to static mailto headers + unsubscribe URL. The caller in
  webhooks.js fires on every Shopify checkout/update event where we may not
  have a Profile._id yet (the profile upsert is async with .then()). The
  poller caller in server.js passes job.profileId.

- UNSUBSCRIBE_HEADERS constant kept in email.js exports for backward
  compatibility (sendAbandonedCartEmail uses it as fallback; test mocks
  reference it).
