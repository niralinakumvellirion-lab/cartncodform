═══════════════════════════════════════════════════════════

Route mount (server.js:172):
  app.use('/apps/cartncodform', proxyRouter);

GET /cod-form is served at /apps/cartncodform/cod-form (proxy.js:297).
The entire proxyRouter is mounted under /apps/cartncodform, which Shopify's
App Proxy forwards with an HMAC-signed query string.

The birthday POST from the cod-form inline JS (proxy.js:594):
  fetch(window.location.origin + '/apps/cartncodform/birthday?shop=' + encodeURIComponent(BOOT.shop), {
    method: 'POST', headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ month: m, day: d, source: 'post_order', phone: phone })
  })

window.location.origin is the Shopify store URL (e.g. https://mystore.myshopify.com).
The fetch goes to /apps/cartncodform/birthday on the storefront. Shopify's App Proxy
intercepts it and adds HMAC signature before forwarding to our backend.

POST /birthday validation (proxy.js:237):
  if (!verifyProxySignature(req.query)) { return 403; }
  (verifyProxySignature = require('../utils/shopify').verifyProxySignature)

AUTH IS CORRECT — request goes through App Proxy and signature is verified.

BUG FOUND + FIXED: The original Phase 3 birthday POST body was:
  JSON.stringify({ month: m, day: d, source: 'post_order' })
  — no `phone`, no `sessionId`.

The /birthday route resolved identity via:
  upsertProfile(shop, { sessionId: sessionId || null }, ...)
  — with sessionId empty string → null → profile not found.

FIX: phone is now included in the POST body. The /birthday route uses:
  upsertProfile(shop, { phone: phone || null, sessionId: sessionId || null }, ...)
Phone has higher merge priority than sessionId (profileService PRIORITY order:
customerId > email > phone > cartToken > sessionId > pushToken).

3. FIRST ORDER — PHONE NORMALISATION + CANCELLED EXCLUSION
═══════════════════════════════════════════════════════════

Phone format:
  Saved to CodOrder (proxy.js:666):   phone: String(phone).trim()
  countDocuments query (proxy.js:712): phone: String(phone).trim()

Both use the same raw-trimmed format → count is consistent for the same
input. Different national-number formats ("+919876543210" vs "9876543210")
from the same person would be counted separately — pre-existing limitation.

CodOrder model status enum: ['pending', 'confirmed', 'cancelled']

BUG FOUND + FIXED: Original countDocuments did not exclude cancelled orders:
  CodOrder.countDocuments({ shopDomain: shop, phone: String(phone).trim() })

If the only order was cancelled, isFirstOrder would be true and the birthday
form would show — incorrect.

FIX (proxy.js:712-714):
  const orderCount = await CodOrder.countDocuments({
    shopDomain: shop,
    phone: rawPhone,
    status: { $ne: 'cancelled' },
  });

SERVER-SIDE BIRTHDAY DEDUP also added: after confirming isFirstOrder, the
cod-order route now queries Profile to check if a birthday is already saved
(proxy.js:716-725):
  const e164 = normalizePhone(rawPhone, 'IN') || rawPhone;
  const bdProf = await Profile.findOne({
    shopDomain: shop,
    'identifiers.phones': { $in: [e164, rawPhone] },
    'birthday.month': { $exists: true, $ne: null },
    'birthday.day': { $exists: true, $ne: null },
  }).select('_id').lean();
  hasBirthday = !!bdProf;

Returned in response:
  { success: true, orderId: order._id, isFirstOrder, hasBirthday }

Cod-form JS condition updated (proxy.js:523):
  if (BOOT.postOrderEnabled && result.body.isFirstOrder && !result.body.hasBirthday) {
  // (was: if (BOOT.postOrderEnabled && result.body.isFirstOrder) {)
