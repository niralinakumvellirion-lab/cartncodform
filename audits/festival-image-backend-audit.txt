====================================================================
Destructuring updated exactly as given:

The `sendPushToCustomers()` call's previously-hardcoded 5th argument
(`null`, meaning this route has NEVER sent an image before — confirmed
via this file's own doc comment above the route and matching the gap
already documented in audits/dashboard-phase1-audit.txt) was replaced
with a computed `imageUrl` local:

  const result = await sendPushToCustomers(shop, title, body, '/', imageUrl, false, null, false);

NOTE ON WHY ONE IMAGE, NOT TWO: sendPushToCustomers() (and the
underlying FCM push payload it builds) takes a single positional
image argument — a push notification has one image slot, rendered by
whichever device the subscribed token belongs to; there is no
per-device image field to fill at send time the way the editor's two
live previews visually mock two different surfaces. The task's own
given formula (`mobileImageUrl || desktopImageUrl || ''`) already
reflects this — mobile is preferred when both are set, falling back to
desktop, falling back to empty string (matching the pre-existing
`null`-effectively-no-image behavior when neither is uploaded).
Implemented literally as given; documented the reasoning inline in the
route's own doc comment as well, so a future reader doesn't wonder why
only one of the two uploaded images is actually used here.

Confirmed the route's own updated doc comment now lists the new body
shape (`Body: { title, body, mobileImageUrl, desktopImageUrl }`) and
references this audit file.
