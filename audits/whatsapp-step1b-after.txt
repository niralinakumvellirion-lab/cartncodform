3. backend/routes/whatsapp.js — purpose support

  Added TZ_COUNTRY map (timezone → ISO 3166-1 alpha-2, default 'IN').
  Added countryFromStore(store) helper.
  Added waOrderMessage template (distinct from waFollowupMessage).
  Added resolveOrderPhone(profile, shopDomain, defaultCountry):
    1. channels.whatsapp.phone (E.164 already stored)
    2. identifiers.phones[]
    3. CodOrder rows linked by email or phone
    4. AbandonedCustomer rows linked by email or phone
    Returns first normalizable E.164, or null.

  POST /:shopDomain/send — extended:
    - Accepts optional body field: purpose: 'followup' | 'order' (default 'followup')
    - followup: requires consentedAt + not optedOut (unchanged semantics)
    - order: refuses if optedOut; resolves phone via resolveOrderPhone; 400 if no phone
    - Job created with purpose field
    - Returns { url, jobId, purpose }

  GET /:shopDomain/stats — extended:
    - sentFollowup = jobs where purpose is undefined or 'followup'
    - sentOrder = jobs where purpose = 'order'
    - sent = sentFollowup + sentOrder
    - canMessageCount = profiles with channels.whatsapp.phone != null
        OR identifiers.phones.0 exists (informational approximation)

  GET /:shopDomain/profile/:profileId — extended:
    - Profile select now includes identifiers (for resolveOrderPhone)
    - canFollowup: consentedAt present + not optedOut
    - canOrder: resolveOrderPhone succeeds + not optedOut
    - orderReason: null | 'opted_out' | 'no_phone' | 'invalid_phone'
    - Messages filtered to channel='whatsapp' (unchanged)

  POST /:shopDomain/opt-out — unchanged.

  No PII logged. All routes remain requireAuth + requireStoreOwner.
