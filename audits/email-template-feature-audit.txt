1. STORE BRAND DATA
─────────────────────────────────────────────────────────────────────────────

WHAT IS FETCHED TODAY
  fetchShopInfo (shopify.js:179–192) calls
    GET /admin/api/2025-01/shop.json
  and reads ONLY:
    s.email       → ownerEmail stored on Store
    s.iana_timezone → store.timezone

WHAT IS STORED TODAY
  Store model has NO brand fields:
    - no shopName / storeName
    - no logoUrl / faviconUrl
    - no brand colors (primaryColor / accentColor / bgColor)
  The only store-name-like field is popup.brandName — a merchant-typed
  string for the push popup, NOT populated from Shopify. Not suitable as
  an email sender name.

SHOP.JSON REST (current call) — extra fields available without extra scopes:
  name, domain, email, currency, money_format, shop_owner, phone, address1,
  country, myshopify_domain. REST does NOT return logo or brand colors.

BRAND API (logo + colors) — GraphQL only
  shop { brand { logo { image { url } } colors { primary { background
  foreground } secondary { ... } } slogan } }
  Available from Admin API 2022-04 onward.
  Required scope: NONE — the Shop object is always readable by an installed
  app regardless of granted scopes. No scope addition needed.

CURRENT SCOPES (shopify.app.toml line 32):
  read_orders, read_customers, write_customers,
  read_products, write_discounts, read_discounts

VERDICT: No scope change is needed to read brand data. A second call in
fetchShopInfo (or a separate fetchBrandData util) querying the GraphQL
Admin API for shop.brand will return logo URL + colors. shop.name is
already on the REST response and should be stored alongside email/timezone.

REUSABLE TEMPLATE: NONE

  function that takes {subject, body, imageUrl, logo, colors} and returns
  a complete HTML document. Every email path builds its own HTML from
  scratch.

5. RESPONSIVE EMAIL REALITY
─────────────────────────────────────────────────────────────────────────────

CURRENT HTML — what works and what doesn't:

  Gmail mobile (app):
    Strips <head> styles. Keeps inline styles. Divs + inline styles mostly
    work. max-width on a div IS respected. border-radius renders.
    ✓ Acceptable with current approach.

  Gmail desktop (web):
    Same as mobile app — inline styles preserved. ✓

  Apple Mail (macOS / iOS):
    Full CSS support including media queries if in <head>. Divs + inline
    styles render correctly. ✓

  Outlook desktop (Windows):
    Uses Microsoft Word's HTML renderer. Critical failures:
    ✗ border-radius → silently ignored (square corners everywhere)
    ✗ max-width on <div> → unreliable; uses a fixed-width <table> instead
    ✗ background-color on <div> → not reliably applied
    ✗ Padding on <div> → partially broken
    ✗ Web fonts (-apple-system, BlinkMacSystemFont) → replaced by Times New Roman
    Without a <table>-based layout + MSO conditional comments, Outlook
    rendering is broken.

  Outlook 365 (web): same as Gmail desktop — acceptable.

WHAT'S MISSING FOR A REAL RESPONSIVE EMAIL:
  1. Full document wrapper:
       <!DOCTYPE html><html><head><meta charset="utf-8">
       <meta name="viewport" content="width=device-width,initial-scale=1">
       <style>/* media queries here */</style></head><body>
     Currently all emails are bare <div> fragments — no doctype, no <html>.
  2. Table-based layout for Outlook (1-column table, 600px wide).
  3. MSO conditional comments:
       <!--[if mso]><table width="600" cellpadding="0"><tr><td><![endif]-->
       (content)
       <!--[if mso]></td></tr></table><![endif]-->
  4. bgcolor attribute on <td> (Outlook background color).
  5. font-family fallback stack ending in Arial or sans-serif (not
     -apple-system which Outlook doesn't recognise).
  6. Explicit width/height attributes on <img> (not just CSS).
  7. Media queries in <head> for true mobile/desktop split (only Apple
     Mail uses them, but worth adding for completeness).
  8. A proper unsubscribe footer with a real link (CAN-SPAM / GDPR).
     The current "reply with unsubscribe" in sendMarketingEmail is not a
     compliant one-click unsubscribe.

  3. POST /api/email-templates/:id/send: sends to a given profileId using
