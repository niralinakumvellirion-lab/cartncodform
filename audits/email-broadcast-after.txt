VALID_SEGMENTS / BROADCAST_CAP / buildEmailSegmentQuery
  Added after VALID_TYPES/EDITABLE_FIELDS. Five segments: everyone, email_captured,
  has_cart, bought_once, going_quiet. Mirror conditions from profiles.js exactly
  (cartTokens.0 exists + orders.count=0 for has_cart; lastSeenAt < 21-day Date
  computed at call time for going_quiet). Always adds shopDomain + suppressed guard
  + $or email-presence guard. Cap = 90 (leaves ~10/day for automated sends).

GET /count declared immediately before GET /:id/preview:
  Position: after POST /generate, before GET /:id/preview and GET /:id.
  Same ordering constraint as /generate — avoids "count" matching :id param.
  Returns { count } from Profile.countDocuments (no profile docs fetched).

POST /:id/broadcast declared immediately before module.exports:
  - IDOR check: template.shopDomain === req.shopDomain
  - Counts FIRST; 400 if 0 or > BROADCAST_CAP
  - Fetches profiles with .select('identifiers channels').lean()
  - Builds HTML once, reuses for all sends (no per-recipient rebuild)
  - Sequential loop; each send in own try/catch; failure tallied, not thrown
  - logBroadcastSend called once after loop with full recipients array
    (channel='email', signalType='email_broadcast', token=email address)
  - Returns { sent, failed, total: profiles.length }

UNSUBSCRIBE_HEADERS: added to every broadcast send call (already in scope
  from the deliverability-improvement import — no new import needed).

Import added: logBroadcastSend from sendLogService.
