(a) PATCH /api/profiles/:shop/popup — partial-update safety
────────────────────────────────────────────────────────────

Confirmed: backend/routes/profiles.js line 780 uses per-key dot-notation $set:

  for (const key of POPUP_FIELDS) {
    if (Object.prototype.hasOwnProperty.call(req.body, key)) {
      set[`popup.${key}`] = ...;
    }
  }
  // same loop for mobilePopup
  await Store.updateOne({ shopDomain: shop }, { $set: set });

Sending a PARTIAL popup object (only the changed keys) does NOT wipe other fields.
Each key in POPUP_FIELDS is a separate $set path; omitted keys are not written.

IMPACT PLAN
────────────────────────────────────────────────────────────────────────────────

New fields:
  Store.popup.buttonTextColor: String ('auto'|'white'|'dark'), default 'auto'
  Store.popup.textMode:        String ('custom'|'auto'|'white'|'dark'), default 'custom'
  (mirrored in mobilePopup)

Validation: invalid enum values are silently dropped (same pattern as other POPUP_FIELDS).
Response: { updated: true, ignored: ['fieldName', ...] } when any keys were dropped.

ccfResolvePopupColors(cfg) → { accent, bg, text, btnFg, dark, muted, inputBg, inputBorder }
  text:  textMode='custom' → cfg.textColor || (dark?'#ffffff':'#111827')  [byte-identical for existing merchants]
         textMode='auto'   → dark?'#ffffff':'#111827'
         textMode='white'  → '#ffffff'
         textMode='dark'   → '#171A22'
  btnFg: buttonTextColor='auto'  → fgOn(accent)  [byte-identical for existing merchants]
         buttonTextColor='white' → '#ffffff'
         buttonTextColor='dark'  → '#171A22'

Storefront:
  - Resolver called once at top of ccfBuildPromptUI (line ~2035)
  - bg/fg/accent replaced by resolver values for all layouts that support those fields
  - ccfAllowButtonStyle gains optional 4th arg (btnFgOverride); default = fgOn(accent)
  - Capture button: uses resolver.text everywhere
  - flash_sale/story_card: hardcoded values unchanged
  - top_bar: tbFg keeps cfg.textColor fallback; allow button uses btnFgOverride

Admin (Discounts.jsx):
  - Wording|Colours top-level view switch within Entry popup panel
  - Colours panel: 4 controls (accent swatch, buttonTextColor, bgColor swatch, textMode/textColor)
  - Disabled for flash_sale/story_card/top_bar
  - Colours save via separate apiSend('/api/profiles/${shop}/popup', 'PATCH', ...)
    triggered by clicking "Save colours" in the Colours panel

Admin (Settings.jsx):
  - textColor onChange also sets textMode:'custom'
