=== DRAG-END-BEFORE-RAF RACE HANDLING ===

Sequence without the guard:
  1. User starts drag → onDragStart fires → rAF queued
  2. User immediately drops outside any valid target → onDragEnd fires → setDragItem(null)
  3. rAF fires → setDragItem(item) — sets dragItem to a stale item with no drag in progress

This causes the calendar to show drag-hover highlights for a ghost drag that is already over.

Fix (dragEndedRef):
  dragEndedRef is a useRef (value persists across renders, mutations don't trigger re-render).
  onDragStart: reset dragEndedRef.current = false before queuing the rAF.
  onDragEnd:   set dragEndedRef.current = true immediately (synchronous, before rAF runs).
  rAF callback: checks if (!dragEndedRef.current) before calling setDragItem(item).
  If drag ends before the frame runs: flag is true → rAF skips the setState → dragItem stays null.
  If drag continues normally: flag is false → rAF proceeds → dragItem set correctly.

Both DayDetailsPanel (uses onCardDragEnd → setDragItem(null)) and the planning list
(calls setDragItem(null) directly in onDragEnd) are covered. onCardDragEnd also calls
setDragOverDate(null) via QueueScreen's handleCardDragEnd. The planning list calls
setDragOverDate(null) directly in its own onDragEnd. Both clear state correctly.
