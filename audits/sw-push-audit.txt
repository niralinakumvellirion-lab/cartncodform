--- Q1: Does the SW handle the `push` event itself with
    self.addEventListener('push', ...)? ---
NO. There is no `self.addEventListener('push', ...)` anywhere in this
file (confirmed by direct read of all 60 lines — the only
self.addEventListener calls are for 'install', 'activate', and
'notificationclick'). Raw push-event handling is NOT done manually;
delivery is handled entirely through Firebase Messaging's own
`onBackgroundMessage()` API (line 18), which Firebase's SDK wires up
internally via its own push listener once `firebase.messaging()` is
initialized in this SW context.

--- Q2: How does it read the push payload? ---
Neither `event.data.json()` nor `event.data.text()` is called anywhere
in this file — there is no raw `event` object in scope at all, because
there is no manual `push` event listener. Instead, the payload is
handed directly to the `onBackgroundMessage(function(payload) {...})`
callback (line 18) already parsed into a JS object by Firebase's own
internal SDK code (which itself listens for the raw `push` event,
calls `event.data.json()`, and reshapes the result before invoking
this callback) — so yes, this SW relies on Firebase's own internal
push-event handling to get from the raw browser push event to a
usable `payload` object; only the FINAL DISPLAY step (title/body/
image extraction + showNotification()) is this file's own code.

--- Q3: Exactly what fields does it read for title, body, icon, image,
    url? ---
Lines 21-36, all with multi-level fallback chains:
  title:  payload.notification?.title || payload.data?.title ||
          'You left items in your cart!'
  body:   payload.notification?.body || payload.data?.body ||
          'Complete your order now'
  image:  payload.notification?.image || payload.data?.imageUrl ||
          payload.data?.image || null
  icon:   payload.notification?.icon || payload.data?.icon ||
          payload.data?.imageUrl ||
          'https://img.icons8.com/color/96/shopping-cart--v1.png'
  url:    payload.data?.url || '/'
Note icon's fallback chain reuses `payload.data?.imageUrl` as an icon
source too (line 34) if no dedicated icon field is present — so the
uploaded banner image can end up used as BOTH the small icon and the
large `image` (this is intentional-looking overlap, not a bug, since
`icon` and `image` are visually different elements in a real OS
notification).

--- Q4: Does it call self.registration.showNotification() itself, or

--- Q5: Is importScripts('firebase-messaging-sw.js') or similar
    present, meaning Firebase's own DEFAULT background handler runs?
    ---
No — this file imports the general Firebase compat SDK scripts
(firebase-app-compat.js, firebase-messaging-compat.js, lines 4-5), NOT
a separate 'firebase-messaging-sw.js' helper script. Because this file

--- Q6: Does it read from payload.data.imageUrl (what the backend
