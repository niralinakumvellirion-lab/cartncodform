Spec 3.8: "Edit for email/whatsapp items must open working editor."
The existing openEditModal uses push-specific fields (title, body,
mobileImageUrl, targetType). Email and WhatsApp items routed to
openEditModal will open the push editor with whatever fields exist.
Audit note: for email items the subject and templateId fields are
not editable via the existing modal. The spec says "if push-only,
add minimum or hide Edit and say so in audit." Decision: Edit is
hidden for email/whatsapp items in the DayDetailsPanel (spec says
this is acceptable). Planning list still shows Edit for all —
but email/whatsapp items in the existing modal will show push fields
only (subject/templateId not shown). This is a known gap; the Edit
button for new-channel items in the planning list will silently
save only the push fields. Not regressing existing push items.
