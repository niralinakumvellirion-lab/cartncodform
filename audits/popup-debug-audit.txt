--- What must be true for showSoftPrompt() to actually get called ---
start() itself never calls showSoftPrompt() directly. It only calls
initIntentTriggers() (after the config Promise.all resolves) and
checkAndInit() (which can independently trigger showSoftPrompt() via a
different path — see below). All roads to showSoftPrompt() run through
one of these:

  (a) initIntentTriggers() — see full function below. Requires, in
      order:
        1. canPrompt() returns true (see section 3/canPrompt below).
        2. getPageType() !== 'product' — OR, if it IS 'product', the
           function has already returned early at that same check,
           so nothing past it runs for product pages via THIS path
           (the return-visit/dwell triggers further down are therefore
           dead code as of the current file — see the code comment at
           lines 1574-1578 explaining exactly this).
        3. Then EITHER:
           - no PAGE_LOAD_TOKEN_KEY in localStorage AND canPrompt()
             still true -> showSoftPrompt('page_load', null) fires
             after a DWELL_MS (1500ms) setTimeout, OR
           - (if hasToken) falls through toward the return-visit/dwell/
             exit-intent triggers, but as noted these are unreachable
             for pageType !== 'product' since pid stays null and the
             'product' branches are skipped; exit-intent (desktop,
             width>768) IS still reachable here regardless of page type.
        4. Trigger 3 (ADD_TO_CART) is wired elsewhere entirely (the
           window.fetch monkey-patch in initTracking(), and trackCart()),
           calling showSoftPrompt('add_to_cart', ...) directly — not
           through initIntentTriggers()'s own body.

  (b) checkAndInit() (called from start(), NOT shown in full here since
      not asked for verbatim — but its relevant call site is documented
      in saveToken(), which checkAndInit()'s 'granted' branch invokes):
      saveToken()'s success handler independently calls
        showSoftPrompt('page_load', null)
      after a 1500ms setTimeout, gated on:
        ccfDiscountEnabled() && canPromptForDiscount() && getPageType() !== 'product'
      — this is the "discount-capture" path for an ALREADY-subscribed
      customer (Notification.permission === 'granted'), using
      canPromptForDiscount() instead of canPrompt() (canPrompt() would
      always reject an already-granted customer, since it requires
      Notification.permission === 'default').

  (c) The product-page nudge (injectProductNudge(), guarded separately
      in start() by `if (Notification.permission === 'granted') return;`
      before it's even called) does NOT call showSoftPrompt() at all —
      it builds its own separate DOM element (#ccf-product-nudge), so
      it is not a path to showSoftPrompt().

Net summary of gating conditions across all paths: browser must support
Notification; permission must be 'default' (canPrompt() path) or
'granted' (canPromptForDiscount() discount-capture path, only if
discounts are enabled); the once-per-session PROMPT_SHOWN_KEY must not
already be set; SUBSCRIBED_KEY (localStorage) must not be '1' for the
canPrompt() path; ccf_denied_session (sessionStorage) must not be set;
ccf_disc_redirected must not be '1' for canPromptForDiscount(); and, for
the page_load trigger specifically, the page must not be a product page
and (for the canPrompt() path) DWELL_MS (1500ms) must elapse first.
