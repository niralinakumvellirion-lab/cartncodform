FIX 1 — Nightly signals survive Render restarts
================================================================================
CONFIRMED.
  - `function scheduleNightlySignals()`, its `scheduleNightlySignals()` call,
    and the `[signals] Nightly signal job scheduled (02:00 server time)` boot
    log were DELETED from server.js. grep "scheduleNightlySignals" server.js
    -> 0 matches.
  - New gate added at the TOP of processScheduledJobs(), inside the outer
    try{}, BEFORE `const now = new Date(); const dueJobs = ...`:
      * Store.find({}, 'shopDomain lastSignalRunAt timezone').lean()
      * per shop: compute today's date in the shop tz (en-CA), build
        target2am = new Date(`${todayStr}T02:00:00`), and
        alreadyRanToday = lastSignalRunAt && lastSignalRunAt >= target2am
      * if (now >= target2am && !alreadyRanToday):
          - Store.findOneAndUpdate({shopDomain}, { lastSignalRunAt: now })  (claim FIRST)
          - runNightlySignals(shop).then(() => runBrainForShop(shop)).catch(...)
          - the 7-day pushStats reset Store.updateMany (moved here from the old
            setTimeout callback per the spec)
      * wrapped in its own try/catch -> `[signals] nightly gate error`
  - setInterval(processScheduledJobs, 30*1000) is unchanged; its log line now
    reads "...(30s interval; nightly signals gated inside)".
  Behaviour: every 30s tick checks the gate; a shop's signals+brain run at most
  once per calendar day (shop tz) once the clock is past 02:00. A restart just
  means the next tick after 02:00 catches up — no run is permanently lost.
  DEVIATION / NOTE: `new Date("YYYY-MM-DDT02:00:00")` (no offset) is parsed in
  the SERVER's local timezone, not the shop's. On Render (UTC) an IST shop's
  nightly effectively fires at ~07:30 IST, not 02:00 IST. It still runs
  exactly once/day and survives restarts (the stated goal). Left as the spec's
  literal code; a true shop-tz 02:00 would need a tz-offset computation.
  DEVIATION: the pushStats reset is placed INSIDE the per-shop
  `if (past 2am && !ranToday)` branch (runs once, for the first shop that
  crosses 02:00 each day) rather than once per tick — cheaper, same effect.
