B. ITEM 2 — Rate-limiter key (backend/routes/discounts.js)
------------------------------------------------------------

BEFORE:
  key = ip|shop
  _WA_RATE_LIMIT = 10

AFTER:
  key = ip|shop|sessionId
  _WA_RATE_LIMIT = 30

WHY: Shopify App Proxy forwards the visitor's real IP as the first
x-forwarded-for entry (confirmed in proxy.js lines 172-174). However,
visitors behind CGNAT or mobile carrier NAT can share a public IP.
Adding sessionId (sent by ccf-embed as body.sessionId) differentiates
them so one visitor's request burst cannot exhaust another's limit.
Limit raised to 30/min — generous for a single popup interaction
per session.

proxy.js updated: passes opts.sessionId = req.body.sessionId to
generateDiscount so the rate-limiter key is populated.

TEST UPDATED (discountConfigRoutes.test.js):
  Rate-limit test now sends 31 requests with a unique sessionId;
  verifies the 31st returns 'Too many requests'.

E. REPORT-ONLY ITEMS (5a–5e)
------------------------------------------------------------

5a. Store link construction
    wa.me URLs are built in backend/routes/whatsapp.js (send endpoint)
    as "https://wa.me/" + toWaDigits(normalized) + "?text=" + message.
    toWaDigits strips the leading "+" from E.164. URL-encoded message
    is built server-side. Link returned to admin frontend as data.url.
    Admin never constructs wa.me URLs directly.

5b. Response shapes
    GET /api/whatsapp/:shop/pending → { total: Number, items: [...] }
    GET /api/whatsapp/:shop/stats  → { pending, sent, clicked, carted,
                                       purchased } (date-scoped)
    GET /api/whatsapp/:shop/profile/:id → { whatsapp: {...}, messages: [...],
                                            canFollowup, canOrder, orderReason }
    POST /api/whatsapp/:shop/send → { url } (wa.me link)
    POST /api/whatsapp/:shop/opt-out → { success: true }

5c. Pending query analysis
    GET /pending uses two sequential queries:
    1. Profile.find({ consentedAt exists, optedOutAt null }) — no index
       currently on channels.whatsapp.consentedAt. For stores with
       <10k opted-in profiles this is acceptable at MVP scale.
    2. ScheduledJob.distinct('profileId', { channel:'whatsapp', ... }) —
       all-time, not scoped to the date window. A profile that received
       a message 6 months ago is still excluded from "pending".
       This is the intended behaviour (once contacted = contacted).

5d. Popup behaviour table (Step 2b)
    action='email'    → waFlagOn=true + consent=true  → saves WA + email
    action='email'    → waFlagOn=false + consent=true → ignores WA
    action='whatsapp' → waFlagOn=true + consent=true  → saves WA, no code
    action='whatsapp' → waFlagOn=false               → error (not enabled)
    action='whatsapp' → consent=false                → error (consent required)
    action='whatsapp' → invalid phone               → error (invalid phone)
    action='push'     → waFlagOn=true + consent=true  → saves WA + push
