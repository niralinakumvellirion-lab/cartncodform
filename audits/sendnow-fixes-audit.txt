FIX 2 — backend/routes/push.js
====================================================================
Added `uploadToCloudinary(base64Data)` as a module-level async
function, placed directly after `const router = express.Router();`
(matching "At top of file add"), exactly as given: reads
`CLOUDINARY_CLOUD_NAME`/`CLOUDINARY_UPLOAD_PRESET` from environment
variables, returns `null` immediately if either is unset, otherwise
POSTs the base64 data + upload preset to Cloudinary's unsigned
`/image/upload` endpoint and returns `data.secure_url || null`. Wrapped
in try/catch exactly as given — any error (network, bad response
JSON, etc.) is caught, logged via `console.error('[push] cloudinary
upload error:', ...)`, and resolves to `null` rather than throwing, so
a Cloudinary outage or misconfiguration can never crash or reject the
POST /send-store request itself.

Confirmed `fetch()` is available as a global in this backend without
any import — checked `node --version` (v24.16.0) and
backend/package.json's `engines.node` field (">=20"); Node 18+ ships a
stable global `fetch`, so no `node-fetch`/`undici` import was needed
or added.

Updated the POST /send-store handler's image-resolution block (added
in the immediately preceding task, audits/base64-strip-audit.txt) to
try the Cloudinary upload BEFORE falling back to stripping, exactly as
given:

  const rawImage = mobileImageUrl || desktopImageUrl || '';
  let imageUrl = '';
  if (rawImage.startsWith('data:')) {
    const cloudUrl = await uploadToCloudinary(rawImage);
    imageUrl = cloudUrl || '';
    if (cloudUrl) {
      console.log('[push] image uploaded to Cloudinary:',
        cloudUrl.substring(0, 50));
    }
  } else {
    imageUrl = rawImage;
  }

The pre-existing `console.log('[push] send-store imageUrl:', ...)`
line from the prior task was kept immediately after this block,
unchanged — it still logs whatever `imageUrl` ends up being (a
Cloudinary URL, an already-real URL passed straight through, or empty
string if upload failed/wasn't configured).

Net behavior:
  - No Cloudinary env vars configured -> uploadToCloudinary returns
    null immediately (no network call attempted) -> imageUrl = '' ->
    same graceful no-image fallback as the prior task, nothing breaks.
  - Cloudinary configured + upload succeeds -> imageUrl = the returned
    secure_url (a real https:// URL) -> passed to
    sendPushToCustomers() -> FCM receives a real, fetchable image URL.
  - Cloudinary configured but the upload call itself fails (network
    error, bad preset, etc.) -> caught inside uploadToCloudinary,
    returns null -> imageUrl = '' -> same graceful fallback, the push
    still sends (just without an image) rather than failing outright.
  - rawImage is already a real URL (not base64) -> the `else` branch
    passes it straight through unchanged, exactly as before.
