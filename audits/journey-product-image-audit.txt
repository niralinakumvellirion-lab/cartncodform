RESOLUTION ORDER (backend/routes/events.js, buildJourneyEntry)
While building productViews, each product_view event's meta.imageUrl is
normalised and, if valid, stored as eventImageUrl on that product. Events
are already reversed to chronological order at that point, so the last
non-empty value written is the most recent one. No extra query.
For each of the top 3 products, in parallel (Promise.all):
  1. ProductImageCache hit (one $in query, as before) -> use it.
  2. Else eventImageUrl -> use it, and upsert it into ProductImageCache.
  3. Else fetchProductImageWithTimeout(shop, productId, 3000).
  Else imageUrl is null.
A cache row whose stored URL fails normalisation is treated as a miss.
eventImageUrl is stripped before returning.


NORMALISATION (backend/utils/productImage.js, normalizeImageUrl)
"//cdn.shopify.com/x.jpg" -> "https://cdn.shopify.com/x.jpg". After that,
anything not matching ^https?:// (empty, null, non-string, relative paths,
data:, javascript:) returns null = missing. Applied to: event og:image,
cached URLs on read, and the Admin API result before it is returned.
Note: the Admin API path's own cache upsert lives inside the unchanged
fetchProductImage and writes Shopify's src as returned (Shopify returns
absolute https URLs). Only the step-2 upsert normalises before writing.


ADMIN API FALLBACK
- Only reached for products still without an image, so at most 3 calls per
  journey entry (topProducts is sliced to 3 before resolution).
- Parallel via Promise.all across the 3 products.
- fetchProductImageWithTimeout races fetchProductImage against a 3s timer
  and resolves null on timeout or any error; it never rejects, and clears
  its timer.
- Limitation: the race abandons the slow call but does not abort the
  underlying fetch(); it finishes in the background and, if it succeeds,
  still writes the cache (harmless).
- It passes accessToken null, so fetchProductImage derives the token from
  the Store row via refreshAccessTokenIfNeeded, same as the webhook path.
  If there is no Store row it returns null.


CACHE WRITE
The step-2 upsert is ProductImageCache.findOneAndUpdate(..., {upsert:true})
wrapped in Promise.resolve(...).catch(() => {}) inside a try/catch, and is
never awaited. A rejection or a synchronous throw is swallowed, so it
cannot fail or delay the response. A test covers a rejecting write.
