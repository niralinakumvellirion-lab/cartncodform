   The exact row counts are an approximation for visual density, not
   a literal per-field mapping — the task didn't specify a count.

2. Saving (`saving === true`): DID NOT reuse ShimmerCard/the shimmer
   gradient for this — a content-shimmer placeholder does not fit
   "keep form visible": the form's real values are already known and
   already rendered; hiding them behind shimmer boxes while saving
   would contradict "keep form visible, just disable inputs" (shimmer
   boxes ARE a form of hiding content). Instead:
   - Disabled inputs: added `opacity: saving ? 0.6 : 1, pointerEvents:
     saving ? 'none' : 'auto'` to the master-toggle header row and to
     all 3 `cardStyle` sections (Send delay, Real-time triggers,
     Active signals) — this keeps every value visibly on screen
     (satisfying "keep form visible") while making the ToggleSwitch/
     DelayInput controls genuinely non-interactive during a save,
     without threading a new `disabled` prop through those two
     reusable components.

     (`inset:0`) inside the SECTION 6 save bar only, shown only when
     `saving` is true. The save bar's existing `position: sticky`
     already establishes a containing block for an absolutely-
     positioned child (per the CSS spec, any position other than
     static — sticky included — does), so no extra `position:
     relative` wrapper was needed. The Save button's own pre-existing
     "⏳ Saving..." text/color/disabled state does the primary
     progress communication; this scrim is intentionally subtle
     (5% opacity tint, no spinner/keyframe) per the task's own word
