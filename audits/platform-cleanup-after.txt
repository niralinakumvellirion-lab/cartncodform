ROOT CAUSE ANALYSIS

  Test structure reviewed for both files:
  - jest.clearAllMocks() in outer beforeEach (clears call state; does not
    reset implementations — handled by nested describe-block beforeEach hooks
    that explicitly re-assign all mock functions each time).
  - Nested describe-block beforeEach hooks reset every mock the block uses
    (Staff.findById, Profile.findOne, Store.exists, etc.).
  - afterEach calls jest.restoreAllMocks() (correct counterpart to spyOn).
  - Rate limiter uses skip: () => isTest so it is bypassed entirely.
  - afterAll calls closeAllConnections() + server.close(done) with 15s timeout.
  - No timers, no real network calls, no shared external state.

  The one structural gap found: server.listen() callbacks did not call
  server.unref(), leaving the server socket able to keep the Jest worker event
  loop alive past afterAll. While --forceExit forces termination, this can
  race with teardown under CI load and produce intermittent assertion failures
  when a worker is killed mid-test.

FIX APPLIED (commit c2e4be4)

  File                                        Change
  ──────────────────────────────────────────  ─────────────────────────────────
  backend/__tests__/platformShoppers.test.js  + server.unref() in listen cb
  backend/__tests__/platformStaff.test.js     + server.unref() in listen cb

  server.unref() tells Node.js not to wait for the server socket when deciding
  whether to exit. The server continues to handle requests normally during
  tests; it just will not prevent the event loop from draining after the last
  test completes. The afterAll still calls closeAllConnections() + server.close()
  for an ordered shutdown. unref() is a belt-and-suspenders guard for the case
  where close() is slow or the worker is recycled before afterAll finishes.
