CONSEQUENCES (behavioural, not a syntax problem):
  a) First saveToken() of a fresh session: redirectDone === false ->
     block always runs.
  b) The guard flag is set ONLY on the happy path (d.code present, line
     1246). If /generate-discount returns { code: null } (no push
     discount configured, backend race, or fetch error), 'ccf_disc_redirected'
     is never written, so any later saveToken() this session (the fallback
     at 1317, a token-rotation re-save, or a duplicate call) will re-enter
     the block and re-POST /generate-discount.
  c) Concurrency: saveToken() can be invoked more than once close together
     (e.g. checkAndInit 1309, plus resync paths / trackCart). Two in-flight
     calls can both read redirectDone === false before either writes line
     1246 -> two /generate-discount POSTs / two redirect attempts.
  d) Loop prevention on the bounced-back page works ONLY when the prior
     pass reached line 1246: after '/discount/CODE?redirect=...' returns,
     start() -> checkAndInit granted -> saveToken -> reads
     'ccf_disc_redirected' === '1' -> logs "discount redirect already done"
     (line 1261) and skips.
