  Notes (observations only):
  * popup state: `const [popup, setPopup] = useState({})` (line 23). Hydrated
    on mount from GET /api/profiles/:shop/popup -> `pop.value?.popup || {}`
    (lines 53-55), the 3rd of five parallel Promise.allSettled requests.
  * The head comment (19-21) is now STALE: it says "the popup customizer lives
    elsewhere now — neither is rendered here", but the popup customizer IS
    rendered here (behind the `showPopupCustomizer` toggle, state on line 26)
    and its fields all bind to `setPopup`.
  * saveSettings() PATCHes twice, sequentially: first `.../settings` with
    { voice, caps, quietHours, timezone }, then `.../popup` with the whole
    `popup` object (line 79). A failure on the first PATCH means the popup
    PATCH never runs (both inside one try).
  * The popup PATCH sends the ENTIRE popup object; the backend
    routes/profiles.js POPUP_FIELDS whitelist is what decides which keys
    actually persist (now includes imagePosition + the redesign fields).
  * `imagePosition` is not initialised client-side — it only exists on `popup`
    once the fetch returns it (schema default 'center center') or the user
    drags the focus control. All read sites use `popup.imagePosition ||
    'center center'` / `|| '50% 50%'` fallbacks.
  * No dedicated popup fetch/save beyond the above — `.../popup` GET on mount,
    `.../popup` PATCH inside saveSettings.

  * 19 fields total, in two comment-marked groups:
    - popup-customizer (original): position (enum, 5), theme (enum: light/
      dark/custom — the Settings UI only offers light/dark), accentColor,
      bgColor, textColor, fontFamily, borderRadius (Number, 12), imageUrl,

      customTitle, showBranding.

      brandName, ctaStyle (enum rounded/square/pill), overlayOpacity
      (Number, 0.5), showOverlay (Boolean, true).
  * imagePosition (line 85) is a plain String with NO enum — accepts both
    keyword pairs ('top left', 'center center') and the percentage pairs the
    drag control now writes ('37% 62%'). Default 'center center'.
  * `customTitle` is legacy (used only by the card layout's old code path);
    the redesign uses `headline` / `subtext` instead.
  * No `_id: false` on the subdoc, no per-field validation beyond the enums,
    no min/max on borderRadius or overlayOpacity.
  * Mongoose applies these defaults when a Store doc is hydrated without a
    `popup` (or without a given sub-key), so GET /popup returns a fully
    populated object even for stores created before the field existed.
