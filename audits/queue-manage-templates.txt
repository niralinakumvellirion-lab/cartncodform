=== SAME-TAB OR NEW-TAB ===

Opens in a NEW TAB (target="_blank" rel="noopener noreferrer").

Why: The Queue Add Engagement flow is entirely React-state driven. There is no
URL-level routing for the individual steps (channel choice, email form, etc.) —
all values (templateId, subject, send time, segment, audience state) live in
useState in QueueScreen. If the user navigated away in the same tab, React would
unmount the component and all typed values would be lost, with no back-button
mechanism to restore them. Opening in a new tab preserves the full flow state.

CustomerDetail opens the link in the same tab because EmailComposer is embedded in
a persistent customer-detail page that already has a stable URL. That situation does
not apply to the Queue flow.

=== LINK PLACEMENT ===

Header row: flex row with justifyContent:space-between. "Choose a template" label on

Both links have aria-label="Manage email templates" for screen readers.
The link is present while loading, on error, and when the list is empty.

=== VISIBILITYCHANGE REFETCH ===

A useEffect in QueueScreen (parent component) adds a visibilitychange listener when
addEngStep === 'email'. On tab-regain (document.visibilityState === 'visible'), calls
doFetchEmailTemplates() — the same function used by the Retry button and openAddEngStep.

doFetchEmailTemplates() uses a functional updater for setAddEngTemplateId:
  setAddEngTemplateId(prev => (prev && !fresh.some(t => t._id === prev) ? null : prev))
This deselects the selected template only if it is no longer in the fetched list;
any still-valid selection is preserved unchanged.

The effect's dependency array is [addEngStep], so the listener is registered only
while the email step is active and is cleaned up when the user navigates to another
step. The eslint-disable-line comment suppresses the doFetchEmailTemplates dependency
warning (the function is a regular component function capturing only stable state
setters, not any state values).
