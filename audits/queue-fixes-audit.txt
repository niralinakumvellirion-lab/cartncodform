FIX 3: One-shot month-jump logic
-------------------------------------
Added `const hasSetInitialMonth = useRef(false);` (new `useRef` import
added to the existing `react` import line) and a useEffect depending on
`[festivalItems, festivalLoading]`.

CONFIRM IT DOESN'T FIGHT MANUAL NAVIGATION
------------------------------------------------
The effect's very first lines are:
  if (hasSetInitialMonth.current) return;
  if (festivalLoading) return;
  hasSetInitialMonth.current = true;
The ref is set to true BEFORE any decision about whether to actually jump
the month — so this block of logic (the "does any item fall in the
displayed month" check, the sort-by-scheduledAt, the upcoming-vs-earliest
selection, and the setCurrentMonth call) executes at most once per page
load, the first time festivalLoading flips to false with items already
present. Deliberately did NOT include `currentMonth` in the dependency
array: the prev/next month buttons call `setCurrentMonth`, which would
otherwise re-trigger this effect on every manual navigation — omitting it
means manual navigation never even re-enters the effect body in a way
that could re-evaluate or override the user's choice (and even if it did
re-run, the ref guard at the top would immediately bail). The "jump"
itself only fires when NONE of festivalItems fall in the month that was
showing at the moment this ran (real-world "now", since currentMonth's
initial state is `new Date()`); if the merchant already has something
scheduled in the current month, no jump happens at all.
