3. DATA FETCHING
----------------
  Promise.allSettled now has FOUR entries (was three):
    1. GET /api/profiles/:shop/weekly-narrative   (kept)  -> narrative, insights, stats
    2. GET /api/profiles/:shop/push-stats          (kept)  -> pushStats
    3. GET /api/profiles/:shop/signals?limit=20    (CHANGED from ?limit=3) -> signals (all)
    4. GET /api/stores/:shop/orders                (ADDED)

  Note on #4: the request is issued per the instruction, but its settled result
  is NOT destructured/consumed. The provided layout derives every "Yesterday"
  number from `stats` + `pushStats` (the instruction states this explicitly:
  "derive 'yesterday' stats from existing data"). Adding an `orders` state var
  that nothing renders would only produce an unused-var lint warning, so the
  4th promise is fired-and-ignored. `GET /api/stores/:shopDomain/orders` is a
  real route (routes/stores.js:36, requireAuth+requireStoreOwner, returns a
  CodOrder array).

  State: narrative, insights, stats, pushStats, signals, loading, error.
  (Removed the old `topSignals` — `signals` now holds the full list.)
  Imports: dropped all @shopify/polaris imports; only `apiGet` remains.
