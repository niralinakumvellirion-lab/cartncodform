10. DEVIATIONS FROM THE LITERAL SPEC (all deliberate)
================================================================================
(a) Icon: CustomersIcon -> PersonIcon (CustomersIcon absent in polaris-icons 9.3.1).
(b) Layout.Section: `oneThird` boolean -> `variant="oneThird"` (v13 API).
(c) Shell does NOT import apiGet/apiSend (STEP 4 "keep" list). They are unused
    in the shell now — every screen imports apiGet from ../../../lib/api itself
    (STEP 5/6). Importing them unused in the shell would only add a lint
    warning. The api capability is retained, just at the screen layer.
(d) Nested <Page>: the shell wraps screens in a bare <Page> (STEP 4), and
    Today.jsx / Customers.jsx each render their own <Page title=...> (STEP 5/6).
    Polaris tolerates a nested <Page> (the outer is just a max-width padded
    container) and the build is clean, but it double-pads. Dropping the shell's
    <Page> (or the screens') is a trivial G2 cleanup — kept both per the
    literal specs.
(e) <Frame navigation={navigationMarkup}> (the `navigation` PROP) rather than
    the spec's `<Frame><Navigation/><Page/></Frame>` (Navigation + Page as
    sibling children). Polaris <Frame> renders `navigation` as the rail and
    `children` as the main region; passing Navigation as a child would render
    it inside the content area, not as the rail. This is the correct Frame API.
(f) Customers row onClick sets `selectedProfileId` but nothing consumes it yet
    (STEP 6: "stub for now, wire in G2"). No modal / navigation happens.
(g) Frame mobile nav: no topBar / burger, so on a narrow viewport the nav rail
    is hidden with no way to toggle it. Desktop-first for G1; the embedded
    Shopify admin gives near-full width, so the rail shows. G2/polish can add
    a TopBar + showMobileNavigation.
