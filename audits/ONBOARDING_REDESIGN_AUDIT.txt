 17	function readDone(id) {
 18	  try {
 19	    return (
 20	      typeof window !== 'undefined' &&
 21	      window.localStorage.getItem(`ccf_step_${id}_done`) === 'true'
 22	    );
 23	  } catch {
 24	    return false;
 25	  }
 26	}
 27	function writeDone(id, done) {
 28	  try {
 29	    window.localStorage.setItem(`ccf_step_${id}_done`, done ? 'true' : 'false');
 30	  } catch (e) {
 31	    /* storage unavailable — the checkbox still updates in-memory */
 32	  }
 33	}

  Notes (observations only):
  * Per-step "done" is persisted ONLY in localStorage (`ccf_step_<id>_done`),
    keyed per browser. The file's own comment (lines 15-16) flags this as a
    CLAUDE.md violation ("No localStorage in the admin (iframe)"). Nothing is
    written to the backend (`Store.onboarding.steps` exists in the schema but
    is not used here).
  * 4 steps: embed / automation / push / cod. Two open external URLs
    (`url` set → Button renders as an external link), two run an `onAction`
    (Settings navigation via `onNavigate`, and `navigator.clipboard` copy).
  * No progress bar — just a "{n} of 4 steps done" heading.
  * Uses `<Page title="Setup">` — since the Polaris Frame was removed from
    page.js this is a bare Page with no app chrome around it.
  * `shop` is interpolated straight into template-literal URLs with no
    encodeURIComponent.

  Notes (observations only) — prototype vs. current implementation:
  * Prototype gates the ENTIRE app behind onboarding: `!onboarded` shows only
    the Onboarding screen and the left-nav items are hidden until `onboarded`
    is true. Current build has no such gate — onboarding is just one nav item
    ("Setup"), always skippable, never forced.
  * Prototype Onboarding has: a "Welcome to CartnCodForm" H1 + one-line
    explainer, a header row with "{done} of 4 done" + a 160px progress bar,
    circular check toggles (not Polaris Checkbox), per-row "Set up" / "Open
    theme editor" / "Send test" buttons that also mark the step done, and a
    footer with "Skip for now" + "Go to Today" (primary, disabled until
    done === 4).
  * Prototype's 4 steps differ from the current file:
      prototype: storefront block · set your voice · choose what to act on · send yourself a test
      current:   enable embed block · configure first signal (Settings) · verify push (add to cart) · share COD form
  * Prototype step 2 ("Set your voice") shows live current voice settings in
    its description; current step 2 just links to Settings.
  * Prototype has NO persistence at all (steps live in App useState);
    current file persists to localStorage. Neither writes to the backend.
  * Prototype `steps` initial state is [true,false,false,false] (step 1
    pre-checked); current file reads all four from localStorage.
