  Query: { shopDomain: { $in: [...] } } → $group _id, count
  Indexes available: compound { shopDomain, identifiers.customerId } (sparse),
    { shopDomain, identifiers.emails } (sparse), { shopDomain, updatedAt: -1 }

Aggregation 2: ScheduledJob sent7d per shopDomain

    Without this, each store in the $in must scan after index lookup.

FINDING H — DOES suspended SURVIVE A REINSTALL?
────────────────────────────────────────────────────────────────────────────────

Uninstall webhook (routes/webhooks.js lines 420-427):
  Store.findOneAndUpdate({ shopDomain }, { plan: 'free', subscriptionStatus: 'uninstalled',
    planUpdatedAt: new Date() })
  → Only three fields are updated. suspended is NOT touched. Stays as-is.

OAuth reinstall callback (routes/auth.js lines 163-166):
  Store.findOneAndUpdate({ shopDomain }, update, { upsert: true, new: true, ... })
  where update (lines 134-161) contains: shopDomain, accessToken, accessTokenExpiresAt,
  installedAt, needsReauth, and optionally ownerEmail, shopName, logoUrl, primaryColor,
  timezone (new install only).
  → Mongoose wraps the plain object in $set, so only the listed fields are changed.
  → suspended is NOT in the update object and is NOT cleared. Stays as-is.

Conclusion: suspended SURVIVES both uninstall and reinstall.
  This is intentional and correct — a platform suspension must persist regardless
  of what the merchant does. A suspended merchant cannot escape enforcement by
  reinstalling.
  No fix required. The behavior is the desired behavior for a platform-level suspension.
