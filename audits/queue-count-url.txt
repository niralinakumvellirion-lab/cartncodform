Old URL (QueueScreen.jsx, line 1608 before fix):
  /api/email-templates/${encodeURIComponent(shop)}/count?segment=${s}

New URL:
  /api/email-templates/count?segment=${encodeURIComponent(s)}

How confirmed against the backend route:
  backend/routes/emailTemplates.js line 204-218:
    router.get('/count', requireAuth, async (req, res) => { … })
  No shop URL segment — shop comes from req.shopDomain set by requireAuth.
  Cross-checked with EmailTemplates.jsx:190 which uses the same corrected pattern:
    apiGet(`/api/email-templates/count?segment=${encodeURIComponent(broadcastSegment)}`)
  The old URL inserted the shop between /email-templates/ and /count, making it
  match the /:id route instead, which would 404 (no template with id="count").

Behaviour confirmed correct by reading the code:
  - null in emailSegmentCounts[seg] → "…" while loading (set via initial state)
  - -1 → "–" on error (catch returns { seg, count: -1 })
  - 0 → emailZeroCount = true → Save disabled + "No customers in this group yet."
  - number > 0 → count shown; Save enabled when template + subject also set

Build result: clean, 0 errors.
