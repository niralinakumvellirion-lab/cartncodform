HOW THE TRACKING LINK IS GUARANTEED

- For default/template path: link is embedded inside the template
  build() call (unchanged path). Also stored in messageText.
- The client NEVER controls whether the link is present; the server
  always ensures it.

RISKS
------
1. Promotional text on an order-purpose send:
   The server enforces only consent/phone eligibility — it does NOT
   validate that the message content is appropriate for the purpose.
   A seller CAN write a promotional/marketing message and send it with
   purpose='order' (which requires no consent). This is a compliance
   risk for WhatsApp Business Policy. Mitigation options (not yet
   implemented): add a UI warning when purpose='order' and text looks
   promotional; or restrict custom messages to followup only. This is
   flagged for a future task.

2. say_hello fallback with custom message:
   If a seller selects say_hello and edits the text, purpose='followup'
   and template=undefined. The backend uses default waFollowupMessage
   path — wait, no: with customMessage present, the server uses
   customMessage (with link appended). The eligibility check (consent)
   still runs for followup purpose. Correct behaviour. ✓

3. Link duplication check:
   The check `customMessage.includes(storeLink)` works because storeLink
   includes the specific ccf_job ID, which is unique per job. Edge case:
   if a customer previously received a different job's link and the
   seller copy-pastes it into the message, the IDs differ and the new
   link is still appended. This is correct behaviour (we always want the
   current job's link). ✓
