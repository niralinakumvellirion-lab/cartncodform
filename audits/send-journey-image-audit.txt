─────────────────────────────────────────────────────────────────────────────
2. IS THE PRODUCT imageUrl AVAILABLE IN THE FRONTEND AT SEND TIME?
─────────────────────────────────────────────────────────────────────────────
Yes — it is already a component-level variable derived from the same customer
prop the rest of the composer reads:

  const productImage = customer?.topProducts?.[0]?.imageUrl || null;
  // CustomerDetail.jsx:397 (NotificationComposer) and :640 (EmailComposer)

`productImage` is used in the UI only — passed to <ProductThumbnail> to show
the small preview alongside the suggestion cards (lines 541, 756). It is
NOT included in either apiSend call.

Source of topProducts[].imageUrl: the customer detail endpoint populates
topProducts from Profile.topProducts, which is written by the storefront
tracking webhook/event pipeline. Shopify product view events carry the
product's Shopify CDN image URL.

─────────────────────────────────────────────────────────────────────────────
3. IS topProducts[].imageUrl AN ABSOLUTE HTTPS URL — NO CLOUDINARY NEEDED?
─────────────────────────────────────────────────────────────────────────────
Yes. Shopify product images are served from cdn.shopify.com:
  https://cdn.shopify.com/s/files/1/0123/4567/products/my-product.jpg

These are:
  - Absolute HTTPS URLs — FCM can fetch them directly.
  - NOT data: URIs — no Cloudinary upload step needed.
  - Publicly accessible — no auth required.
  - Well under typical image-size limits.

The Cloudinary upload step in /send-store and processFestivalQueue exists
only because the admin editor's ImageUploadPair component produces a base64
data: URI (FileReader-based). Journey sends use product images, not editor
uploads, so no conversion is needed — the URL can be passed straight through
to sendPushToCustomers.

4. SMALLEST CHANGE TO MAKE /send-journey INCLUDE THE PRODUCT IMAGE
─────────────────────────────────────────────────────────────────────────────
Two files, four lines total. No new helpers, no Cloudinary logic.

FRONTEND — CustomerDetail.jsx, NotificationComposer.send():
  Change:
    await apiSend('/api/push/send-journey', 'POST', {
      profileId: customer.profile._id,
      title,
      body,
      url: ...,
    });

  To:
    await apiSend('/api/push/send-journey', 'POST', {
      profileId: customer.profile._id,
      title,
      body,
      url: ...,
      imageUrl: productImage || undefined,   // ADD — undefined omits the field
    });

BACKEND — push.js, sendJourneyPush():
  Change:
    async function sendJourneyPush(shopDomain, { profileId, title, body, url })
  To:
    async function sendJourneyPush(shopDomain, { profileId, title, body, url, imageUrl })

  Change:
    const result = await sendPushToCustomers(
      shop, title, body, url, null, false, cartToken
    );
  To:
    const result = await sendPushToCustomers(
      shop, title, body, url, imageUrl || null, false, cartToken
    );

The route handler itself needs no change — req.body.imageUrl flows through
the { ...args } spread into sendJourneyPush automatically once it's in the
destructured parameter.

Wait — the route calls:
  const { profileId, title, body, url } = req.body;
  sendJourneyPush(req.shopDomain, { profileId, title, body, url });

req.body.imageUrl is NOT passed through this destructure. The route handler
also needs to be updated:
  const { profileId, title, body, url, imageUrl } = req.body;
  sendJourneyPush(req.shopDomain, { profileId, title, body, url, imageUrl });

So the full diff: 3 backend lines + 1 frontend line.

sendPushToCustomers already handles the imageUrl for both webpush.notification.image
and data.imageUrl — no changes needed in pushNotification.js.

─────────────────────────────────────────────────────────────────────────────
ROOT CAUSE SUMMARY
─────────────────────────────────────────────────────────────────────────────
/send-journey was built without an imageUrl parameter. The variable
`productImage` (= topProducts[0].imageUrl) is already computed in the
NotificationComposer component and used for the card thumbnail, but was never
wired into the API call. The backend function has the matching null slot in
its sendPushToCustomers call. Because topProducts images are Shopify CDN
HTTPS URLs, no Cloudinary step is needed — they can be forwarded directly.
