task's suggested literal — `{ channel: '...', type: '...', sentAt: new

using the task's literal shape would have silently broken the function
(job.profileId would be undefined on the reconstructed object, so
`if (!job.profileId) return;` would fire immediately and the message
would never be recorded at all). Fixed using the real 4-field contract
instead, per "Do NOT change the recordProfileMessage() function signature
itself" — the function's inputs are unchanged in meaning, only guaranteed
to now be plain values rather than live-document getters.
