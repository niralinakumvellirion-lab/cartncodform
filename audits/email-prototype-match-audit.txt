6. STICKY OFFSET
------------------------------------------------------------

PROTOTYPE VALUE
  top: calc(70px + env(safe-area-inset-top, 0px))
  70px was chosen assuming a standard desktop app-bar height.

SHOPIFY IFRAME REALITY
  The admin screen runs inside the Shopify App Bridge iframe.
  There is NO 58px Shopify app bar inside the iframe.
  The iframe viewport starts at the top of the content area.
  The correct sticky offset is just the grid gap above the stage:
    top: 12px   (matches prototype's 16px gap − 4px rounding, or simply
                 the --gap value)
  lib.js already exports STICKY_TOP = 12 (lib.js:12). This is correct.

AVAILABLE HEIGHT
  Shopify admin iframe is approximately 630px tall.
  With top:12px sticky, the stage has ≈618px of usable vertical space.
  The stage padding (14px×2) leaves ≈590px for the mailbox + bar.

ACTION
  Change the prototype's sticky calc to top:12px (or var(--gap)) for
  the production build. No change to lib.js needed (already 12).


7. PREVIEW — COLLAPSE FIX STATUS
------------------------------------------------------------

CONFIRMED: the PreviewStage collapse fix is NOT yet in the code.

Three bugs compound (full analysis in audits/email-preview-ux-audit.txt):

BUG A1 — measureNatH returns 8 on blank srcdoc.
  PreviewStage.jsx lines 34–46:
    function measureNatH(iframe) {
      if (!iframe) return 600;
      try {
        const doc = iframe.contentDocument;
        if (!doc || !doc.documentElement) return 600;
        iframe.style.height = '1px';
        const h = doc.documentElement.scrollHeight || 600;
        //          blank doc → h ≈ 8 (truthy) → || 600 never fires
        iframe.style.height = h + 'px';
        return h;
      } catch { return 600; }
    }
  No threshold guard (h < 100) is present. blank doc gives h=8.

BUG A2 — fit() not called after pushToIframe direct DOM update.
  PreviewStage.jsx lines 21–32 (pushToIframe):
    // When readyRef.current === true (normal path):
    s.textContent = out.css;
    doc.body.innerHTML = out.body;
    // ← no fit() call here
  Lines 193–205 (draft/store debounce effect):
    pushToIframe(df, out);
    pushToIframe(mf, out);
    // ← no setTimeout(() => fit(), 50) follows

BUG A3 — Mobile scale = 100% when mH=8.
  PreviewStage.jsx (inside fit()):
    kM = Math.min(1, usableH/mH, usableW/MOBILE_W)
    // mH=8 → usableH/8 >> 1; usableW/391 ≥ 1 when pane ≥ 391px
    // → kM = 1 → scale badge "100%" → visH = 8px

FIX DIRECTION (audit only — do not implement here):
  After each pushToIframe call in the draft/store effect:
    setTimeout(() => fit(), 50);
  Also add a threshold guard in measureNatH:
    if (h < 100) return 600;   // blank doc or not-yet-rendered
  And push lastOut when mobile iframe first mounts (deviceView change).


8. RISKS AND FILES TOUCHED
------------------------------------------------------------

RISK: Tab removal — vertical scroll UX
  Removing 6 tabs and showing all 5 cards at once means the editor
  panel becomes 5× taller. On the 980px narrow layout, the user would
  need to scroll through all cards to reach Words/Send. Mitigations:
  anchor links at the top, or collapsible card headers (low effort).
  Risk: MEDIUM.

RISK: Splitter removal — fixed column widths
  The prototype's 430px left column is a maximum (minmax(0,430px)).
  At 1280px viewport: left=430px, right≈820px — plenty of space.
  At 1024px: left=430px, right≈572px — still sufficient.
  At 980px: single column. No content loss.
  Risk: LOW.

RISK: localStorage removal — user preference lost
  Users who had saved a custom split ratio will get the default on
  next load. One-time mild surprise; no data loss.
  Risk: LOW.

RISK: PreviewStage collapse fix — iframe timing
  setTimeout(fit, 50) is a heuristic. Slow machines may need 100ms.
  Consider using a MutationObserver or the iframe's onload instead.
  Risk: LOW-MEDIUM (test thoroughly on real device).

RISK: ColourCard always-visible palette
  Current expandable "Pick colour" section hides the 32-colour swatch
  grid behind a click. Prototype shows it always. Expanding it adds
  ~180px of height to the Colours card. Acceptable in a scrollable
  panel; may feel long in a tab. Lower risk once tabs are removed.
  Risk: LOW (with tabs removed).
