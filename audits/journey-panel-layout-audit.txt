NOTE - applied to both of the Send-notification section's two
mutually-exclusive branches, not just one
=========================================================================
The task said "Find the Send notification card (second card, ~line
876)" as if there is a single card. Reading the actual code (the IIFE
starting at "Send notification panel"), there are actually TWO
different divs that can render as this second card, chosen by an
if/else that never renders both at once:
  1. The no-channels fallback (`if (!hasPush && !hasEmail) return
     (<div style={{background:'#f9fafb', ...}}>...No push
     subscription or email on file...</div>)`) -- shown when the
     selected customer has neither push nor email.
  2. The real composer card (`return (<div style={{background:'#fff',
     ...}}>...Send notification heading, tab switcher,
     NotificationComposer/EmailComposer...</div>)`) -- shown
     otherwise.
Applying the flex/scroll styling to only one of these two would leave
the OTHER one still using the old plain block sizing whenever it's the
one that happens to render -- for the specific case this task exists
to fix (a customer with a lot of journey timeline content AND an
available notification composer), branch 2 is what actually matters
most, but branch 1 can just as easily render for a different selected
customer and would then sit inside the same fixed-height, flex-column
sticky wrapper without a matching `flex: '0 0 auto'` of its own,
potentially disrupting the same layout the fix is meant to guarantee.
Applied the identical 3 style properties to both, so the fix holds
regardless of which customer is selected.
