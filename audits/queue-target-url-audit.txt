CONFIRM buildClickUrl OUTPUT FOR BOTH targetType VALUES
------------------------------------------------------------
Traced (not executed against a live server, but the logic is a pure,
3-line function with no async/IO — traced by reading):
- targetType 'home' (or anything other than the literal string
  'product', or omitted entirely): returns `https://{shopDomain}` —
  the shop root, same destination the old bare '/' was presumably
  *intended* to mean.
- targetType 'product' WITH a non-empty productHandle: returns
  `https://{shopDomain}/products/{productHandle}`.
- targetType 'product' but productHandle is '' or falsy: falls through
  to the `https://{shopDomain}` return (the `&& productHandle` guard in
  the if-condition catches this) — never produces a malformed
  `.../products/` URL with a missing handle.
