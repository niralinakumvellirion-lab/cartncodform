WHY #3
  Fixes #1 (blind poll) and #2 (afterInteractive + onLoad event)
  both still failed because App Bridge v4 needs to be loaded by a
  SYNCHRONOUS <script> (no async / no defer). In the Next.js App
  Router, next/script inside a Client Component can't guarantee
  that. The only reliable place is a plain <script> in the root
  layout's <head>, which the browser fetches + executes before it
  parses <body> — so window.shopify exists before any client
  component mounts.

================================================================
1. frontend/app/layout.js — CHANGE (exact)
================================================================
  layout.js uses `export const metadata = {...}` and renders an
  explicit <html>/<body> with NO <head>. Added a <head> block
  containing the plain App Bridge <script>:

  BEFORE:
    export default function RootLayout({ children }) {
      return (
        <html lang="en">
          <body>
            <Providers>{children}</Providers>
          </body>
        </html>
      );
    }

  AFTER:
    export default function RootLayout({ children }) {
      return (
        <html lang="en">
          <head>
            {/* App Bridge must load synchronously (no async/defer) — a plain
                <script> in the root layout <head> is the only reliable way in
                the Next.js App Router. Do NOT switch this to next/script. */}
            <script src="https://cdn.shopify.com/shopifycloud/app-bridge.js" />
          </head>
          <body>
            <Providers>{children}</Providers>
          </body>
        </html>
      );
    }

  The <script> tag as added (verbatim):
      <script src="https://cdn.shopify.com/shopifycloud/app-bridge.js" />

  - Plain <script>, NOT next/script. No async, no defer -> the
    browser blocks on it during <head> parsing and window.shopify
    is populated before <body> / React hydration.
  - The `export const metadata` (title / description) is
    unchanged; Next merges it into <head> alongside this <script>.
  - It now loads on EVERY route (marketing, login, dashboard,
    admin) — harmless: on a non-embedded page App Bridge just
    doesn't attach window.shopify (no parent frame), and only the
    /admin code ever calls window.shopify.idToken(). ~1 extra
    network request on the other pages.
  - The per-page dynamic <meta name="shopify-api-key"> stays in
    admin/page.js (it can't live in the static root layout).

3. frontend/lib/api.js — new getAuthToken() (exact)
================================================================
  async function getAuthToken() {
    if (typeof window === 'undefined') {
      throw new Error('Not running in browser');
    }
    let waited = 0;
    while (!window.shopify) {
      if (waited >= 10000) {
        throw new Error('App Bridge did not initialize');
      }
      await new Promise(resolve => setTimeout(resolve, 100));
      waited += 100;
    }
    return await window.shopify.idToken();
  }

  - Reverted to a simple bounded poll (100 ms interval, 10 s cap).
  - The 'shopify:ready' event listener, the parallel setInterval,
    and the 8 s inner timeout from fix #2 are all GONE.
  - Because App Bridge now loads synchronously in <head>,
    window.shopify is almost always already present on the first
    call; the loop is just a small safety margin for the very
    first render, and the 10 s ceiling still fails cleanly on a
    genuinely non-embedded load.
  - Everything else in api.js (BACKEND_URL, describeNetworkError,
    apiGet, apiSend) unchanged. The explanatory comment above
    getAuthToken was updated to describe the head-<script> load.
