LOGIC ADAPTED (beyond pure JSX) — 2 items, both forced by the
task's mapping rules:

  (A) window.confirm  ->  Polaris <Modal destructive>.
      REASON: window.confirm is a synchronous, blocking browser
      primitive; a Polaris Modal is declarative and stateful, so
      the confirm gate cannot be preserved "byte-for-byte" while
      using a Modal (which the task explicitly requires:
      "Confirmation dialogs (if any) -> <Modal> with destructive
      prop").
      WHAT CHANGED:
        - added state `deleteTarget` (the rule pending deletion, or null)
        - `deleteRule(rule)` no longer does the confirm + delete
          inline; it now only opens the modal: `setDeleteTarget(rule)`
        - new `confirmDelete()` contains the EXACT original
          try/catch body — same apiSend('DELETE', .../rules/{_id}),
          same `loadRules()` on success, same
          `catch (err) => setError(err.message)`. Only the gate
          in front of it moved from `if (!window.confirm(...)) return`
          to "user pressed the modal's Delete button".
        - the confirm copy is preserved verbatim in Modal.Section:
          `Delete "{deleteTarget?.name}"? This cannot be undone.`
      NOT CHANGED: the delete API call, the endpoint, the reload,
      the error handling.

  (B) ResourceItem requires `url` OR `onClick` (verified in the
      installed 13.9.5 d.ts: `ResourceItemProps = PropsWithUrl |
      PropsWithClick`). The source's per-rule card was NOT
      clickable as a whole. To satisfy ResourceItem's contract I
      wired `onClick={() => setEditingRule(rule)}` — the same
      action as the explicit "Edit" button that is still present
      inside the item. Polaris ResourceItem natively ignores
      clicks that originate on nested interactive elements
      (Button/link/input), so the inline Edit / Pause|Resume /
      Delete buttons keep working independently and do NOT also
      trigger the row onClick.
      NET UX DELTA: clicking the body of a rule row now opens the
      editor (it previously did nothing). Minor, additive, and
      the only way to use ResourceItem as the task's mapping
      ("List of rules -> <ResourceList> with <ResourceItem>")
      demands. No state/API/handler logic added beyond the
      existing setEditingRule.

  TRIVIAL JSX-ONLY changes (not behavior):
    - the `if (showForm || editingRule)` branch dropped its
      `<div className="mt-6">` wrapper and returns <RuleForm />
      directly (RuleForm is now a self-contained <Card>; the
      Tailwind top-margin was dashboard-page spacing that the
      Polaris <Page> layout in Stage 2c will own).
    - `"{step.title}"` literal quotes -> `&quot;{step.title}&quot;`
      (and same in the Modal body) — identical rendered output,
      lint-safe, matches the &apos; style already used elsewhere
      in admin/page.js.
    - Active/Paused pill -> <Badge> (same as StatusBadge's
      Tailwind-color -> Polaris-tone approach).
